# 产品需求

## 问题

开发者在多个本地仓库之间工作时，经常需要先打开系统终端、切换目录，再启动 Claude Code、Codex、Antigravity、Grok Build 或 Hermes Agent CLI。这个流程重复且容易出错。

CLI Launchpad 0.3.0 将项目选择、CLI 会话切换和终端交互收进一个本地桌面工作台。0.4.0 在这一基础上扩展为本地项目工作区：用户可在同一窗格体系中管理终端、项目文件和文档预览，并通过 Git 管理分支、工作区变更和远程同步。

## 目标用户

主要用户是需要频繁在多个本地项目中使用 AI CLI 工具的开发者。

## 工具范围

0.3.0 目标只聚焦五个 CLI：

- Claude Code CLI：`claude`
- Codex CLI：`codex`
- Antigravity CLI：官方主命令 `agy`
- Grok Build CLI：官方命令 `grok`，终端简称 `GB`；通过独立 G1 里程碑接入。
- Hermes Agent CLI：官方命令 `hermes`，终端简称 `HA`；通过独立 G2 里程碑接入。

其他 CLI 不进入当前产品范围。

Antigravity 是 Google 新品牌下的目标 CLI。本项目不再关注 Gemini CLI，也不提供 Gemini CLI 的检测、安装或启动入口。

## CLI 适配范围

五项 CLI 的差异由按 `ToolKey` 注册的适配器承接，包括安装与版本探测、更新命令、工作台启动与会话恢复、历史来源解析、检索字段标准化，以及品牌图标和展示文案。工作台布局、PTY 生命周期、执行任务并发与缓存、历史索引和搜索、数据库去重与界面状态由公共层负责。

适配器按 CLI 拆分公共实现与平台实现；仅在操作系统行为确有差异时提供 Windows、macOS 或 Linux 覆盖实现，其余复用共享实现。该机制只服务已确认的五项 CLI，不开放任意 CLI 插件或自动发现。

## MVP

- 持久化常用项目目录。
- 内置五个默认工具：Claude Code CLI、Codex CLI、Antigravity CLI、Grok Build CLI、Hermes Agent CLI。
- 为每个 PTY 会话记录项目归属、CLI 类型和可选 CLI 对话关联。
- 在单一工作区中管理来自多个项目的 PTY 会话；支持同一项目启动多个 CLI 或同一 CLI 的多个独立会话。
- 支持递归嵌套的多窗格工作区；每个窗格在自己的标题栏中切换所属 PTY 会话，横向/纵向分栏边界可像 VS Code 一样拖动调整窗格大小。布局只引用 PTY，不拥有或关闭 PTY。
- M3 持久化当前工作区并支持命名布局快照；切换快照只调整主工作区的终端视图布局，不启动、迁移或终止 PTY 进程。快照未引用的主工作区会话优先保留在原窗格（先匹配稳定 pane ID，再匹配窗格编号）；无对应窗格时放入所应用布局的焦点窗格。独立窗口会话继续留在独立窗口，不参与布局合并或窗格重排，即使快照包含该会话也不将其挂回窗格。
- 自动生成的终端标题使用短 CLI 名称：Claude Code 为 `CC`、Codex 为 `CDX`、Antigravity 为 `AGY`、Grok Build 为 `GB`、Hermes Agent 为 `HA`。其他界面继续显示完整 CLI 名称。
- 窗口序号按项目和 CLI 全局递增；独立窗口中的会话也占用序号，不因分栏布局应用而重新编号。
- 支持拖动活动标题或堆叠列表中的会话在窗格间移动同一 PTY；移动后清空的源窗格保留，便于继续安排会话。可通过标题菜单将单个会话打开为独立终端窗口；独立窗口只承载一个终端，不提供分栏。关闭独立窗口会把同一 PTY 会话送回主工作区当前激活窗格，不终止进程；独立窗口中的 CLI 自然退出时，窗口自动关闭并移除对应 slot。
- 尝试支持把独立窗口中的终端标题拖回主工作区窗格；若 Windows WebView 间的系统拖放不能可靠工作，独立窗口必须提供明确的“返回工作区”操作作为等价入口。
- 普通启动使用 CLI 默认行为；恢复历史会话时仅附加对应 CLI 所需的内部恢复参数。
- 右侧为 Claude Code、Codex、Antigravity 提供独立的内置终端启动按钮；按 CLI 检测结果启用或禁用。
- xterm 支持终端选中文本复制到系统剪贴板，以及从系统剪贴板粘贴文本；Windows 文本快捷键为 Ctrl+Shift+C/V，保留 Ctrl+C 中断 CLI。
- Windows 图片粘贴快捷键按 CLI 分派：Claude Code 使用 Alt+V、Codex 使用 Ctrl+V；图片留在系统剪贴板，应用只向 PTY 传递按键，不传输图片数据。Antigravity 图片粘贴不在当前承诺范围内。

## 0.4.0 本地工作区能力

0.4.0 以已有项目目录为唯一工作区入口，不提供仓库克隆。文件浏览、文本编辑、Markdown 预览、Git 状态与远程协作均围绕用户已登记的项目目录展开。

- 右栏提供项目上下文、文件管理和 Git 管理三个页签。项目上下文保留 0.3.0 的 CLI 启动与会话历史。
- 文件管理按需浏览当前项目中的目录与文件；文本文件可在中央窗格打开、编辑和保存。
- 中央工作窗格可承载 PTY 终端、Monaco 文本编辑器和 Markdown 预览。共享窗口宿主统一负责标题、标题右侧关闭按钮、焦点、关闭当前/其他/全部、拖动换窗格、右键菜单、独立窗口、分栏和布局恢复；内容适配器只声明容器内渲染、内部交互、类型标签、受限服务能力与可选生命周期钩子。
- 工作区内容项共享激活、关闭、拖动换窗格、右键操作与独立窗口外壳。宿主通过适配器标签和类型安全回调表达“关闭文件/终端”等差异；PTY 的会话进程和终端交接继续由 workspace coordinator/Rust service 管理；文件交接项目内路径、运行期编辑缓冲和版本标识，脏内容受保护，不持久化正文。
- Markdown 使用连续滚动渲染，支持可切换文档主题和仓库已有的 ECharts Markdown 能力；不提供分页和文档导出。
- Git 管理提供当前分支、工作区状态、分支操作、变更文件、差异、暂存与提交，并支持在编辑器中查看 blame 与增删行标记。
- Git 远程支持 remote 管理、认证交互、fetch、push、快进拉取、rebase 与冲突处理。认证复用系统 Git、凭据助手、系统凭据存储和 SSH agent；Launchpad 不独立存储 Git 密码、令牌或私钥。
- Git 作为可选系统依赖进行检测。Git 缺失时，项目、终端和文件编辑仍可使用，Git 功能显示可操作的安装/配置提示。

### 编辑器与适配器扩展边界

- 内建工作区内容以启动期动态注册方式组合，避免把各类窗口行为分散在组件中的大型条件分支。窗格生命周期和授权由应用公共层掌握，内容适配器只提供类型行为。
- Monaco 首期提供常用语言语法高亮、基础编辑命令及主题适配；定义跳转、跨文件引用等语义能力需要后续语言服务/LSP，不能仅依赖 Monaco 的语法支持。
- 文件元数据缓存、全文搜索和语言语义索引为不同能力：缓存只保存可重建的项目内元数据，全文搜索按需读取文件，语义索引由语言服务管理。
- M6 不加载第三方插件。未来插件必须单独定义 API 版本、权限与能力授权、隔离、签名和升级机制；注册适配器不代表授予任意代码访问文件系统或执行进程的权限。
- 项目目录、相对文件路径、Git 仓库状态和用户文件内容分别遵循项目根目录安全边界；应用仅持久化工作区恢复所需的文件引用和布局元数据，不复制项目文件正文到 SQLite。

## 界面形态

CLI Launchpad 0.3.0 采用大窗口优先的工作台布局，完整设计见 `docs/ui-design.md`：

- 左侧项目区维护项目名称并选择 CLI 启动和会话恢复的目标项目。
- 中央主区是纯终端工作区，跨项目展示终端窗格；标题和会话切换跟随各自窗格，支持多级横向/纵向分栏及可拖动边界，不显示项目标题栏或脱离窗格的全局标签条。
- 右侧上下文区提供五枚直接启动按钮，并按时间合并显示所选项目的五项 CLI 历史会话；支持本地标题/摘要搜索。
- 普通 CLI 启动不提供外部终端选项或命令预览；历史恢复直接在内置 PTY 中完成。
- 设置、安装更新、执行任务、备份和关于作为轻量辅助区域，不抢占终端主画布。
- 主工作区和独立终端窗口使用统一的应用自定义标题栏；主窗口的侧栏、布局与窗口操作入口固定在顶部，左侧项目区不再放产品 Logo/名称。macOS 保留原生红黄绿交通灯；其他平台由应用提供窗口控制按钮。
- 托盘、关闭窗口和窗口恢复沿用现有桌面能力，并适配工作台上下文；再次打开时恢复最近的窗口尺寸和位置，显示器布局变化后将窗口收回当前可用工作区。

## 核心对象与会话归属

- **项目**：持久化项目名称和本地目录，作为 PTY 的稳定归属。
- **PTY 会话**：运行中的进程、终端缓冲和尺寸状态；每个 PTY 有独立标识、CLI 工具、标题和项目目录。
- **CLI 对话**：五项 CLI 自身持久化的历史会话；可与 PTY 关联，但未能可靠识别时允许为空。
- **工作区布局**：在主窗口的全局工作区内排列来自任意项目的 PTY 面板。当前工作区在 M3 自动保存；命名布局是显式保存的快照。独立终端窗口可临时呈现其中一个会话。窗格移动、独立窗口打开/关闭和布局编辑只改变呈现位置，不复制或终止 PTY。
- **文件文档**：由项目 ID 与项目内相对路径标识；编辑缓冲仅驻留运行期内存，保存写回原文件。窗格布局可持久化文件引用，不持久化正文。
- **Git 仓库状态**：从项目目录中的 Git 仓库和系统 Git 实时读取；分支、index、worktree 和 remote 仍以仓库自身为事实来源。
- **内容窗格**：可呈现终端、文本编辑器或 Markdown 预览；具体内容类型由带版本的窗格引用恢复，各适配器不接管项目或 PTY 生命周期。

左侧选择项目只改变启动/恢复目标，并高亮该项目关联的窗格；其他项目的 PTY 仍留在同一工作区并继续运行。终端进程退出后，其会话窗口自动关闭，但窗格及分栏关系保留为空状态；移动会话留下的空窗格也保留，存活会话不受影响。用户可在空窗格中启动 CLI，或从右侧历史会话恢复。独立窗口关闭时，会话仍由应用管理并返回主工作区当前激活的窗格；窗格移动、窗口开合不得产生第二个 PTY 或重复输入/尺寸控制。隐藏主窗口到托盘时应用仍在运行，所有 PTY 继续运行。用户显式退出应用时，如果存在活动 PTY，必须先说明将结束这些终端；用户取消则继续留在应用，确认后结束由应用托管的 PTY 进程树再退出。关闭单个终端只结束对应 PTY；编辑、切换或删除布局不能隐式终止 PTY。

PTY 子进程由应用拥有，不脱离应用成为后台服务。正常退出必须结束所有托管 PTY；应用异常退出时，平台进程隔离必须结束托管 PTY 子进程树，系统重启时进程随系统终止。这些行为在 M1 实现和验证，并在 M5 跨平台复验。应用重启后不接管仍存活的进程：旧运行会话从当前工作区移除，保留原窗格树、编号、比例和焦点；命名快照本身不改写，应用快照时会省略已结束会话项并保留窗格。用户可在选定空窗格中重新启动 CLI 或从该 CLI 的历史会话恢复。终端输出和滚屏缓冲只驻留内存，不持久化。布局恢复仅恢复面板上下文，不代表原 PTY 进程仍在运行。应用启动时不自动运行 CLI。失效项目或会话身份仍以局部诊断占位项呈现，不阻止其余窗格恢复。

## 启动方式

0.3.0 的 CLI 启动统一在应用内创建 PTY。右侧五个品牌按钮各自直接启动对应 CLI；未检测到的 CLI 禁用。普通启动不提供外部终端入口、平台终端选择或命令预览；PTY 启动失败时在工作台显示错误，不静默切换到其他窗口。启动继续使用 Rust 解析出的完整 CLI 路径、结构化参数和经过校验的项目目录。

### 0.2.x 外部终端兼容基线（历史需求，已不再适用）

> **状态（2026-10-06）：** 以下需求描述 0.2.4 的外部终端启动能力。该能力已在 0.4.0 M6 期间连同终端探测与启动代码整体删除，当前版本不再提供外部终端入口、平台终端选择、Windows Terminal Profile 保留或命令预览；这些条目仅作为历史需求保留，用于理解 0.2.x 数据与旧文档，不构成当前验收条件。当前启动需求以上文“启动方式”为准。

- 启动目标由 Rust 返回平台中立的终端环境，设置值使用稳定 target ID；`auto` 在当前平台选择推荐目标，跨平台数据库中的不可用显式目标自动退回 `auto` 候选链。
- Windows 自动模式优先选择 Windows Terminal 默认 Profile，并尽量保留该 Profile 的命令、参数、外观和初始化行为。
- Windows Terminal Profile 按能力分为完整追加、PowerShell 命令续接和仅保留外观三种保留级别，设置页允许显式选择检测到的 Profile。
- Windows Terminal 不可用或启动失败时，依次回退到 PowerShell 7、系统 Windows PowerShell 和 CMD；最终兜底允许牺牲 Profile 配置，但必须保证存在可用启动路径。
- macOS 自动模式固定使用系统内置 Terminal.app；检测到 iTerm2、Ghostty、WezTerm 或 kitty 时允许用户显式选择，不因安装第三方终端而自动改变行为。
- Terminal.app、iTerm2、Ghostty、WezTerm 与 kitty 是当前完整支持的 macOS 终端目标。
- macOS 的 Terminal.app 与 iTerm2 启动载荷必须位于应用缓存目录、权限限制为当前用户可执行、在开始执行后自删除，并在应用启动时清理超龄残留；Ghostty 使用原生 AppleScript 窗口接口，WezTerm 与 kitty 使用应用包内 CLI；目录、工具路径和参数只在最终 POSIX Shell 边界引用。
- macOS 终端探测必须复核应用 Bundle ID 与所需包内可执行文件，不执行候选应用；显式目标不可用或启动失败时回退 Terminal.app。
- 启动前的命令预览必须展示实际选中的终端、平台相关保留能力和失败回退链。

## 会话历史

应用应能读取并展示已有的 CLI 会话历史，支持快速恢复之前的会话：

- 在项目上下文中合并展示五项 CLI 的历史会话，按 CLI 分别分页；恢复时直接创建对应的内置 PTY。
- Claude Code 优先读取 `sessions-index.json` 的摘要，Codex 优先调用 App Server `thread/list`，两者失败时回退到本地 JSONL。
- Antigravity 从本机 `conversation_summaries.db` 与 conversation metadata 只读匹配当前 workspace，并支持按 conversation id 恢复。
- Grok Build 从 `~/.grok/sessions/` 下官方会话摘要 metadata 读取会话标识、项目目录、标题/摘要和活动时间；恢复使用 `grok --resume <session-id>`。只读取摘要文件，不读取 transcript 或 `updates.jsonl`。
- Hermes Agent 从当前有效 Hermes home 对应的单个 `state.db` 只读读取 `source=cli` 的会话 metadata；遵循 `HERMES_HOME` 和 Hermes 活动 Profile 解析结果，不枚举、切换或管理其他 Profile。按 `git_repo_root` 或 `cwd` 匹配项目，并以经过长度限制的短预览辅助列表和本地搜索。恢复使用 `hermes --resume <validated-session-id> --no-restore-cwd`，固定留在当前项目目录；不读取其他 source、不查询 Hermes 全文 FTS。Windows 安装使用官方 CLI 安装器的非交互模式，并跳过工作台不提供的可选浏览器与 computer-use 工具。
- 会话搜索限定当前项目，使用可重建的本地 SQLite 索引匹配五种 CLI 实际展示的标题、summary，以及受限的首条用户消息或 preview；FTS5 trigram 提供忽略大小写的子串匹配，1–2 个字符使用短词回退。索引在项目激活或手动刷新时有界更新，查询不重新扫描 CLI 文件。最多返回 2,000 条，前端按 10 条展开；清除搜索或切换项目后释放前端结果。索引只保存短 metadata，不保存完整对话正文或项目路径；用户别名仍由业务 SQLite 持有并在查询时合并。不使用 Grok 原生 `grok sessions search` 或 Hermes 全文检索，因为工作台的搜索只覆盖本地受限 metadata。
- 每个 CLI 首次只展示最新 10 条会话，用户点击“更多”时再加载 10 条；不同 CLI 的分页状态相互独立。
- 会话标题优先使用 CLI 保存的摘要或名称；用户可以按 `tool_key + session_id` 设置本地别名，也可以删除别名恢复原始标题。
- 会话历史实时读取事实来源，不将标题摘要或源文件路径持久写入应用缓存。
- 本地别名只在用户手动重命名时写入 SQLite，不把普通会话同步到应用数据库。

## 项目维护与 CLI 启动

- 项目列表固定在左侧，只展示项目名称；添加和编辑通过弹窗完成，编辑支持重命名并保留原目录路径。
- 左侧项目菜单提供置顶、打开目录和移除等项目操作；移除项目不得删除用户目录或误结束仍在运行的 PTY。
- 右侧项目上下文区提供五个独立的 CLI 内置启动按钮，并合并展示所选项目的历史会话。
- 不提供全局或项目级自定义启动参数、模型选择、手动模型输入或外部终端启动选项；普通 PTY 使用 CLI 默认行为。
- 历史会话恢复保留 Claude、Codex、Antigravity、Grok Build、Hermes Agent 各自必需的内部恢复参数；恢复前重新验证会话归属当前项目。
- 0.2.x 数据库中已保存的参数不执行、不在新 UI 中编辑；旧配置导入时忽略参数字段，新配置导出不再包含参数。

## 版本检测与更新

设置页提供 CLI 版本管理能力：

- 检测五个 CLI 的可用路径和最新可用版本；被动检测不自动执行候选程序，用户主动刷新时才对解析后的完整路径执行有界版本探测。
- 对有新版的 CLI 提供应用内更新入口，执行对应官方更新命令。
- 更新与安装遵循同一原则：先预览命令、用户确认、输出日志、完成后重新检测。
- 更新来源必须来自官方：Claude、Codex、Antigravity、Grok Build、Hermes Agent 分别使用官方支持的更新机制；Grok 与 Hermes 更新前识别安装来源，不能确认来源时不执行托管更新。

## 执行任务与历史日志

安装与更新不在确认浮层内等待完成。用户确认后创建后台执行任务，并通过左侧“执行任务”顶层导航查看：

- 每个任务展示准备中、执行中、正在终止、执行成功、执行失败、已取消、已超时或意外中断状态。
- 标准输出和错误输出实时追加到任务日志；应用重启后仍可查看历史任务和日志。
- 同一 CLI 同时只允许一个安装或更新任务运行；不同 CLI 的任务可并行执行，并分别维护状态、日志和终止控制。
- 执行中的任务允许用户主动终止；Windows 使用 Job Object，macOS 使用独立 Unix 进程组，两个平台都必须终止完整进程树，并明确提示更新中断可能需要重新安装对应 CLI。
- 默认只保留最近 50 个任务，每个任务最多持久化 1 MiB 日志；超过上限时记录截断状态和提示。
- 支持清理单个历史任务或全部历史任务，清理前必须再次确认；执行中的任务不能清理。
- 仅持久化五个内置 CLI 已批准的结构化安装/更新计划，不接受自由命令，也不保存环境变量或密钥。

## 依赖检测

应用应提供启动前或设置页中的依赖检测能力：

- 检测 `claude`、`codex`、`agy` 是否可用。
- Antigravity 以 `agy` 为主；`antigravity` 只作为保守兼容探测，不作为推荐启动命令。
- 在 PATH 或可信已知安装目录解析到完整路径时判定为可用，否则判定为未安装。
- macOS 不执行用户 Shell 启动脚本来补全 GUI 进程 PATH；除当前进程 PATH 外，只扫描 `~/.local/bin`、Homebrew、Volta、NVM 等限定的可信用户级安装位置。
- 展示实际解析路径；当前版本或最新版本查询失败时保留安装状态，并显示独立失败原因。

## 一键安装

Claude、Codex、Antigravity 的官方一键安装已在 0.2.x 基线实现；Grok Build 在 G1、Hermes Agent 在 G2 增加官方安装支持。0.3.0 保留确认、后台执行、日志和重新检测流程，并从工作台提供入口。

一键安装必须满足：

- 只覆盖 `claude`、`codex`、`agy`、`grok`、`hermes` 五个 CLI。
- 安装前展示安装来源和完整命令。
- 安装来源必须来自官方文档或官方推荐包。
- 用户确认后才执行。
- 输出安装日志。
- 安装完成后自动重新检测。
- 安装失败时展示可操作的错误信息和手动安装建议。

## 非目标

- 不使用 Electron。
- 不提供远程后端。
- 不提供多用户账号系统。
- 不做代理、模型路由或密钥管理。
- 不做通用 CLI 工具管理器。
- 不建设额度查询、Agent 编排、Git worktree 管理、远程运行或移动端控制平台。
- 0.4.0 不克隆仓库，不提供分页式 Markdown 排版、PDF/Word 导出或完整 IDE/VS Code 扩展体系。

- 0.3.0 不提供 CLI Launchpad 自身的自动更新或后台版本检查；后续可基于 GitHub Releases 单独设计。
- 不检测或安装当前范围外的 CLI 工具。

## 数据归属

SQLite 是功能配置的事实来源：

- directories
- tools
- shell profiles
- per-directory tool arguments
- launch history
- application settings（包括关闭窗口行为）
- execution tasks 与执行日志
- 手动创建的稀疏会话别名
- PTY 会话元数据、自动保存的当前工作区布局与命名布局快照（M1/M2/M3 分阶段验收）
- CLI detection cache（存放在独立可删除的 `cache/cache.db`）

CLI 历史标题等 metadata 不进入业务数据库；工作台显示和恢复列表仍读取各 CLI 的权威来源。为支持项目内搜索，可重建的短 metadata 索引保存在独立缓存数据库，按项目 ID 隔离，不保存源文件路径或完整对话正文。只有用户显式设置的会话别名进入业务数据库。历史全局/项目参数存储结构为 0.2.x 兼容数据，不再作为有效配置。

本地 UI 偏好后续可使用 JSON 或 Tauri store：

- 窗口尺寸和位置
- 主题
- 上次选择的目录和工具
