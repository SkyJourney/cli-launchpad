# M8：本地 Git 管理与编辑器联动

## 目标

在项目目录中提供本地仓库、分支和工作区变更管理，并将 Git diff、blame 与行级状态连接到 M6 编辑器。

## 依赖与设计门禁

- 依赖 M6 文件服务、内容窗格和编辑器。
- Git 作为可选系统依赖检测；本阶段采用 Rust 受控进程服务调用系统 Git，不新增 libgit2。
- 选定稳定、机器可解析的 Git 输出协议；工作树状态由 Git 实时查询，Launchpad 不复制提交历史。
- 明确 stage 与 worktree 差异、行标记、blame 延迟加载和缓存失效规则。

## 范围

- 检测 Git 可执行文件和当前项目仓库；支持仓库根目录与子目录项目映射。
- 展示当前分支、本地分支及 upstream/领先落后状态；提供创建、切换、重命名和安全删除本地分支。
- 展示 staged、unstaged、untracked 变更及基本 rename 状态；显示 ignore/子模块等暂不支持状态时不得伪装为空仓库。
- 查看 staged 和 unstaged diff；将工作树文件与暂存版本分别送入编辑器/差异查看。
- 文件树和 Git 变更列表打开同一项目相对路径时聚焦已有编辑器内容。
- 支持选择性暂存/取消暂存和本地提交；提交前显示目标分支与 staged 文件，空提交或 hooks 失败可理解返回。
- 编辑器对跟踪文本显示相对 HEAD 的新增/修改/删除 gutter 标记，并按需显示 Git blame 行归属。
- 记录 Git 操作进度、退出码和清理；日志中的远程 URL 必须脱敏。

## 非目标

- 本阶段不实现 remote 管理、网络 fetch/push、pull、rebase、冲突解决。
- 不管理 Git worktree，不克隆仓库，不提供完整提交历史浏览或图形提交图。

## 任务清单

1. 对系统 Git 版本、Windows/macOS/Linux 安装发现、仓库发现和输出协议做预研。
2. 设计 Rust Git service、结构化请求/响应、任务取消/超时和错误分类。
3. 实现仓库/分支/状态/差异/索引/提交命令及外部变更后刷新。
4. 实现编辑器 gutter、blame 查询和文件状态失效。
5. 为提交钩子、凭据敏感输出和异常退出建立隔离与日志规则。
6. 完成跨平台仓库矩阵、代码审查及本阶段最终门禁。

## 验收覆盖

- 仓库矩阵：非仓库、主仓库、子目录、bare repository、分支缺失、unborn branch、detached HEAD。
- 状态矩阵：staged/unstaged 混合、untracked、rename、删除、空格/Unicode 路径、忽略目录、子模块和冲突状态。
- 操作矩阵：分支创建/切换/重命名/删除保护、部分暂存、提交成功、提交钩子失败、用户取消和外部 Git 操作并发。
- 安全：命令参数边界、远程 URL 脱敏、超时、输出上限、被删除或符号链接替换的文件。
- 编辑器：行标记对比 HEAD、暂存和未暂存 diff 分别正确；blame 对未跟踪文件不可用时显示合理状态；提交后标记刷新。
- 实机：Windows、macOS、Linux 检查系统 Git 探测、UTF-8/Unicode 文件名、长路径、主题行标记和多窗格回归。

## 验收条件

- Git 缺失或当前项目非仓库时，文件、编辑器和 PTY 仍可工作并给出 Git 状态说明。
- 本地分支、状态、diff、暂存、提交、blame 和编辑器行标记以系统 Git 当前事实为准。
- 不存在前端自由命令执行、秘密写日志或未提交改动被分支切换静默覆盖的路径。
- M8 自动门禁和三平台适用验收通过，才能启用 M9 网络操作。
