# Grok Build CLI 接入

**状态：** 规划中，待开始
**版本与里程碑编号：** 待定
**依赖：** 0.3.0 工作台完成；官方工具能力调研通过

## 目标

将 Grok Build 作为独立 CLI 接入 CLI Launchpad，沿用现有三个 CLI 的轻量工作台交互方式，使其在项目归属和内置终端工作流中保持一致。

## 启动前调研

- 核实 Grok Build 的官方产品、官方命令名称和受支持平台，优先使用官方文档或发布渠道。
- 核实 Windows 下的检测、安装、更新与版本识别方式，并确认是否适合由应用内置 PTY 启动。
- 核实 CLI 是否提供项目相关的会话历史、会话标识和恢复入口；如果不支持，不仿造或缓存其私有会话格式。
- 对照现有 CLI 的检测状态、项目归属、启动失败反馈、终端交互和历史恢复体验，明确能力差异与安全边界。

## 初步范围

- 为 Grok Build 增加独立的检测、状态展示和内置 PTY 启动流程。
- 终端会话标题使用 `项目名-GB-序号` 格式；其他界面仍展示官方完整产品名称。
- 会话归属当前项目，并遵循现有 PTY 的生命周期、进程隔离、输入输出和关闭规则。
- 仅在官方能力和可靠性满足要求时提供历史列表及会话恢复；具体数据源、命令参数和验收标准由启动前调研确定。
- 安装与更新仅在存在可信官方来源且完成安全评估后纳入；不得从非官方来源推断安装命令。

## 验收框架

正式启动该里程碑时，补齐详细的产品范围、架构决策、实施任务、自动化测试、Windows 实机验收和发布门禁。至少验证：

- 官方命令和版本检测能区分可用、未安装与执行失败状态。
- 在 Windows 项目目录内可以通过内置 PTY 启动并正常输入、输出、调整尺寸及退出；异常退出不遗留失管进程。
- Grok Build 会话与项目正确关联，不串入其他 CLI 的状态或历史。
- 如支持历史恢复，需验证历史来源、项目归属校验及恢复参数；如官方不支持，则明确记录为不提供此能力。
- 若纳入安装或更新，需验证官方来源、用户可见的执行计划、任务状态、日志、取消和完成后的版本回读。
- 代码审查、修复复审和最终门禁按届时里程碑计划完成，并记录未能执行的跨平台检查。

## 当前状态

此文档仅预留后续独立里程碑，不代表已经确认 Grok Build 的官方命令、产品能力、平台支持或交付版本，也不改变 0.3.0 当前三个 CLI 的范围。
