# M5：跨平台验收与 0.3.0 发布

**状态：** Windows 阶段已完成；macOS M0–M4/G1–G4 已由用户确认阶段验收通过；Linux 验收待完成，之后执行 CI 全 target 矩阵构建和 0.3.0 发布门禁
**依赖：** M1–M4、G1–G4
**目标：** 为 0.3.0 建立可靠的跨平台发布候选。

macOS/Linux 实机验收在 Windows 版 M1–M4、G1–G4 完成后集中开展，目前正在推进 macOS 代码对齐。M1–G4 分散文档中的平台实机检查均已收敛到[跨平台对齐待办](cross-platform-alignment.md)，该清单及其逐平台记录是唯一验收来源。

Windows 的 0.3.0 x64 NSIS 本地候选包已完成干净构建、升级本机 0.2.4 安装及启动核对。此结果只证明 Windows 本地候选可运行，不等于正式发布门禁通过；正式 tag 和 GitHub Actions 发布需等待 macOS/Linux 对齐、M5 全部验收及用户确认。

## 范围

- 在 Windows、macOS、Linux 覆盖 PTY 生命周期、项目切换、多个会话、分栏布局、 CLI 恢复和窗口/托盘行为。
- 检查高频终端输出、Unicode、中文输入法、主题、复制粘贴、快捷键和窗口尺寸变化。
- 按统一清单验收 M1 PTY、M2 工作区、G1/G2 CLI、M3 布局、G3 窗口标题栏和 G4 主题/生命周期/适配契约在 macOS/Linux 的行为；确认 G4 语义 token 矩阵和 CLI 能力在各平台一致。
- 通过 CI 或平台主机完成 macOS/Linux Tauri 配置、Rust 目标编译、前端生产打包和安装包构建；检查窗口能力、平台依赖及 SQLite schema/迁移兼容。
- 验证旧版本升级、异常退出、进程终止、数据库迁移和布局恢复。
- 构建 Windows 在线/离线 NSIS、macOS ARM64/Intel DMG、Linux x64/arm64 deb/rpm/AppImage。
- 更新 README、截图、安装说明、已知限制、发布说明和版本入口。

## 非目标

- 不以未完成的自更新、远程运行、移动端配套或 Agent 编排阻塞 0.3.0。

## 验收条件

- [ ] 三个平台的打包和安装成功，应用显示统一品牌图标。
- [ ] 每个平台至少完成一项 CLI 的真实交互启动验收；五项 CLI 的平台安装/检测/更新来源、PTY 参数和历史能力均有逐项证据。Grok Build 的 macOS/Linux 结果须分别记录，不能由通用 Unix 实现或另一平台验收代替；未安装或不适用项注明原因，不要求未经用户安排就实际执行会改动设备的安装/更新。
- [ ] 单终端关闭、退出确认/取消、托盘隐藏、异常终止、系统重启和布局恢复均符合 M0 定义的进程生命周期语义。
- [ ] 布局失效、PTY 退出、项目移动/删除和 CLI 对话不可匹配均有可理解的 UI 状态。
- [ ] 从 0.2.4 数据升级的迁移验证通过，保护恢复点可用。
- [ ] 用户文档反映 0.3.0 新布局、支持范围、升级和已知限制。
- [ ] M0–M4、G1–G4 验收记录完整；所有未通过项有明确延期决定。

## 产物

- 三平台验收记录及发布构建产物；M1–G4 的 macOS/Linux 实机验证统一按跨平台对齐待办执行。
- 0.3.0 发布说明与更新后的用户文档。
