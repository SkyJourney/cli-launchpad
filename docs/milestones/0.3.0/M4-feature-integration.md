# M4：现有能力接入与数据迁移

**状态：** 已完成

**依赖：** M2、M3、G1–G4

**目标：** 确认 0.2.4 用户的业务数据能安全进入 0.3.0 工作台，并复核既有辅助能力已在新工作流中形成完整入口。

M4 的工作台能力已随 M1–G4 分阶段实现。本阶段不重复建设已交付功能，重点补齐旧版数据升级的端到端证据、检查配置交换与恢复边界，并修复审查发现的问题。M4 当前只覆盖 Windows；macOS/Linux 对齐与实机验收统一由 M5 承接。

## 0.2.4 数据基线

- 0.2.4 数据库使用 schema 8，包含项目、工具配置、旧版全局/项目参数、应用设置、执行任务和稀疏会话别名。
- 0.2.4 配置 bundle 为 v3；当前 bundle 为 v4。旧参数字段须忽略，新导出不包含这些字段。
- 当前数据库 schema 为 13。启动时先检查既有数据库完整性和版本；有待执行迁移时先建立 SQLite 一致性保护备份，再按事务逐版本应用迁移。
- 0.2.4 与当前版本使用相同的 Tauri 应用标识。主题、语言和工作区面板开合等 WebView 本地偏好沿用原存储身份；业务设置由 SQLite 保存。历史 `dev.local.cli-launchpad` 数据目录和窗口状态迁移逻辑继续保留，迁移不删除源文件。

## 已交付能力（本阶段复核，不重复实现）

- 设置页提供五项 CLI 的检测、版本与安装/更新入口；安装更新任务在后台运行，可查看实时日志、取消及历史状态。
- 项目上下文区提供五项 CLI 的历史、受限 metadata 搜索、别名和原生恢复；恢复创建内置 PTY 并归入全局共享工作区。
- 设置页提供配置 JSON 导入导出、SQLite 备份恢复、诊断导出及桌面关闭行为设置。
- 工作区当前状态和命名布局保存在 SQLite；备份包含布局，配置 bundle 不导出或覆盖布局。
- 旧全局/项目参数留在兼容数据库结构中，但新启动链不读取；旧 bundle 参数字段被忽略，新 bundle 不导出参数。
