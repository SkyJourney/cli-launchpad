## 历史分阶段任务与验收记录

每个平台独立记录和验收；可按设备可用性选择先后，不以一个平台的结果替代另一个平台。

1. **建立目标机基线：** 记录系统/桌面环境、CPU 架构和工具链；运行 Tauri 配置校验、Rust 测试与目标平台 Release 编译、前端构建，先解决阻塞构建的问题。
2. **补齐平台实现：** 优先按官方文档完成 Hermes 在该平台的安装、版本/更新策略和来源保护；复核五项 CLI 的可用性探测、PTY 启动/恢复参数和历史数据路径，并补充平台单测。
3. **验证工作台交互：** 按共通清单验收 PTY 生命周期、输出/输入、窗格与布局、主/独立窗口、主题同步、项目/会话状态和异常恢复；修复平台差异后回归。
4. **打包和升级验收：** 构建平台产物，在目标桌面实际安装、启动、升级旧数据并验证图标、依赖、托盘和卸载/重装行为；记录证据或逐项延期理由。

阶段 1 的实际目标编译通过后再进入阶段 2；阶段 2/3 的缺陷闭环后再执行阶段 4。CI 产物可辅助验证打包，但不能替代各平台的交互和安装检查。
