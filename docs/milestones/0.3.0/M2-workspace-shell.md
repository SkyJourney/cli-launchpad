# M2：跨项目共享终端工作台

**状态：** Windows 阶段已验收完成（用户实机确认工作台、窗格拖动、空源窗格保留、独立窗口拖回及提示清理；跨平台对齐纳入 M5）
**依赖：** M1
**目标：** 将主窗口改为以项目归属和跨项目 PTY 会话为中心的共享工作区。

## 范围

- 采用大窗口优先的三栏布局：左侧项目导航、中间共享终端区、右侧 CLI 启动与会话恢复区；中间不显示项目标题栏。
- 左侧支持项目名称搜索、置顶、添加和项目菜单操作；新增/编辑使用弹窗，编辑可重命名并保留路径，列表行不显示路径。
- 右侧按当前目标项目提供三枚独立的内置 CLI 启动按钮和跨 CLI 合并历史会话恢复；普通启动不接受自定义参数或模型覆盖，也不提供外部终端入口或命令预览。
- 中间以递归分栏树管理跨项目 PTY 窗格；每个窗格拥有自己的标题栏和会话切换项，不使用脱离终端窗格的全局标签条。
- 窗格标题栏完整展示当前活动会话；其余会话按活动项前后堆叠于左右入口，展开后可切换、关闭、右键操作或拖动。标签栏不显示横向滚动条；活动标题过长时换行并自适应增高。
- 默认终端标题格式为 `项目名-CC-序号`、`项目名-CDX-序号`、`项目名-AGY-序号`，缩短标题并保留项目与 CLI 辨识度；完整 CLI 名称仍用于其他界面。
- 窗格从初始主窗格“窗格-1”开始编号；窗格标题和“移至窗格”目标使用相同名称。删除窗格不重编号现存窗格，新建窗格复用当前最小空缺编号。
- 支持一个项目多个 CLI/同一 CLI 多开；横向、纵向及多级分栏可组合，分隔边界可像 VS Code 一样拖动调整相邻窗格大小。
- 支持从活动标题或堆叠会话列表拖动到现有窗格，移动同一个 PTY 并激活目标窗格；源窗格清空后保留。终端标题右键菜单可将会话打开为独立 Tauri 窗口。
- 独立窗口只呈现一个终端，不支持分栏；窗口关闭默认把同一 PTY 交还给主工作区当前聚焦窗格，若目标 pane 已失效则回到根窗格。提供显式“返回工作区”入口。
- 尝试支持把独立窗口的终端标题拖回主工作区指定窗格；若 Windows WebView 的跨窗口 HTML 拖放不能稳定传递会话标识，保留显式“返回工作区”入口并将跨窗口拖放限制记录为验收结果。M2 不要求把主窗格标题拖出应用生成独立窗口。
- 终端标题支持右键菜单：左右/上下拆分、拆分并移入此终端、移动至已有窗格、关闭此终端及关闭同窗格其他/全部终端；批量关闭只确认一次。右栏折叠按钮固定在左侧品牌标题行右侧，不跟随聚焦窗格。
- 点击项目只改变启动/恢复目标并突出显示其关联窗格；其他项目会话继续留在共享工作区并保持可操作。
- PTY 退出后自动关闭对应窗格会话项；窗格及分栏关系保留为空状态，可用于启动 CLI 或定向恢复历史会话。
- 执行任务、设置、关于沉到侧栏底部图标；适配托盘显示、窗口关闭确认、PTY 持续运行与重新打开行为。
- M2 布局状态仅在应用运行期有效，不保存命名布局；保存、恢复和已结束会话占位由 M3 完成。
- 当前只验收 Windows；macOS/Linux 实机对齐按[跨平台对齐待办](cross-platform-alignment.md)安排在 Windows M1–M4 完成后执行，并纳入 M5 门禁。

## 非目标

- 不提供通用 IDE 式任意插件面板或任意窗口编排；仅支持窗格间终端移动和单会话独立窗口。
- 不在 M2 保存/加载命名布局预设或跨重启恢复 PTY 布局。
- 不改变三项 CLI 的安装、更新与认证逻辑；不再暴露自定义启动参数或模型选择。

## 验收条件

- [x] Windows 应用以大窗口工作台启动；首次使用显示添加/选择项目入口，不自动启动 CLI；中央终端区不显示项目标题。
- [x] 左侧只展示项目名称；名称搜索、添加弹窗、编辑重命名弹窗、置顶、打开目录和移除操作均可用，移除不会删除磁盘目录或误结束活动 PTY。
- [x] 右侧三枚 CLI 启动按钮按检测状态启用/禁用并直接启动内置 PTY；历史列表合并三项 CLI 并按最近活动排序，恢复创建独立 PTY、验证项目归属且仅携带 CLI 必需恢复参数；普通启动不应用旧全局/项目参数，也不显示外部启动或命令预览。
- [x] 同一项目可启动多个同 CLI PTY；多个项目、三个 CLI 会话可同时出现在同一工作区，输入、输出、尺寸、关闭和错误均按 session ID 隔离。用户确认新版工作台组合场景验收通过。
- [x] 每个窗格的标题、会话切换与终端视图相连；所有窗格显示唯一编号，空窗格也能从标题识别；“移至窗格”菜单与窗格标题编号对应。删除窗格不重编号现存窗格，新建窗格复用当前最小空缺编号。同一窗格可以切换多个会话，且焦点会同步项目上下文。
- [x] 横向/纵向分栏可递归组合；拖动任意分栏边界能连续改变相邻窗格尺寸，尺寸比例随拖动更新；同一 PTY 不会被重复挂载或误终止。
- [x] 拖动窗格标题到其他窗格后，终端标题、TUI 屏幕状态、输入、输出及尺寸跟随同一 PTY 迁移；原窗格保留为空，目标窗格不创建第二个 PTY。用户 Windows 实机确认拖动后会话可继续操作。
- [x] 从标题右键菜单打开独立窗口后只显示一个 PTY；CLI TUI 状态和滚屏画面连续，输入与尺寸由独立窗口控制。关闭独立窗口或选择“返回工作区”时，会话回到当前激活窗格；失效时回退根 pane，过程中不终止进程。
- [x] 窗格间拖动及独立窗口标题拖回目标窗格通过 Windows 实机验收；用户确认拖回后会话保持运行，成功投放后所有窗格拖动提示均清除。
- [x] 交接失败回滚、令牌和窗口归属校验、超时恢复、快照/尺寸边界与重复交接保护已完成代码审查；Rust 服务单测覆盖交接超时、输出序号和快照边界。Windows 实机确认独立窗口返回/关闭后会话仍可在主工作区使用。
- [x] 终端标签右键菜单始终对准被点击会话；拆分、拆分并移动、移至已有窗格及明暗主题外观通过 Windows 手工验收；审查发现关闭非活动会话时的焦点限制并已修复。
- [x] 左侧选中项目会高亮所有相关窗格并设为启动目标，不隐藏、重排或关闭其他项目会话；聚焦会话后项目上下文与右侧历史同步。
- [x] PTY 自然退出或被确认关闭后，对应会话项自动消失；窗格树、分栏比例及其他会话保持不变；空窗格可继续启动或恢复会话。
- [x] 拆分后每个终端实际尺寸始终在安全边界内；空间不足时阻止继续拆分/显示明确提示，不提交零尺寸或危险尺寸。
- [x] 窄窗口、常规窗口和最大化窗口均可使用主要操作；右侧面板和左侧导航按空间折叠，终端仍可输入与滚动。

## 设计决策

- 主窗口默认尺寸为 1360×860，保留现有最小窗口尺寸；窄窗口优先折叠右侧启动/历史面板，再压缩左侧项目区。
- React 以 session ID 索引 PTY 元信息，以递归 split tree 维护窗格、窗格编号、窗格内会话列表、活动项和分栏比例；Rust 继续拥有真实 PTY。窗格编号在窗格仍存在期间保持稳定，新建时选择最小未占用正整数。创建、焦点、缩放和退出均以会话槽位映射的 PTY session ID 路由。
- 每个 pane 节点包含唯一会话槽位 ID 列表与活动槽位 ID；槽位映射到启动后产生的 PTY session ID，避免创建前后更换 React 终端实例。稳定的会话注册区以 portal 容器挂载 xterm；pane 分栏或重新布局时移动容器，不重建终端实例或 PTY 事件连接。每个 split 节点包含方向、比例和两个子节点。Allotment 提供 VS Code 风格的可拖动分栏边界与最小尺寸约束，React 持有运行期比例。
- 标签右键操作引用被点击的会话槽位 ID；移动仅调整递归布局归属，不创建或终止 PTY。批量关闭由工作区统一确认一次，再按 session ID 调用各 PTY 终止入口。
- 跨窗格拖放只改变 pane 归属；弹出为独立窗口时使用 Tauri 一次性标签和事件通道进行 PTY 所有权交接。Rust 在序号水位上暂停/暂存有界输出，xterm 序列化当前画面；目标窗口恢复快照并在提交所有权时应用自己的实际尺寸，然后重放之后的输出并接管输入；失败则回滚至原视图。各可见 pane 的活动终端分别同步本 pane 尺寸，窗格聚焦只负责路由用户输入。窗口关闭时以同一流程交还给主窗口当前 pane，若 HTML 跨窗口拖放不可用，显式返回操作作为受支持的回收路径。
- Windows 主窗口和独立终端窗口关闭 Tauri 原生文件拖放处理，让 WebView 的 HTML 拖放事件承载会话标题；拖放载荷只包含运行期会话槽位、源窗格/窗口标签，目标窗格必须再次核对当前会话归属。拖放不写入 SQLite，也不接受外部文件作为会话。
- 独立窗口的 session ID 来自经过 Rust 校验的临时交接状态，不把 URL 查询参数当作可信项目/CLI 数据；同一 session ID 在主 pane 和独立窗格之间严格单归属。M2 不持久化独立窗口位置或独立窗口清单。
- 会话只归属一个 pane。新建分栏生成空窗格并聚焦；从右侧启动或恢复时将新会话加入当前聚焦窗格。同一 PTY 不会重复挂载。
- PTY 运行期间保留其终端模拟器实例与屏幕缓冲；窗格内未选中的会话保持挂载但隐藏，不发送零尺寸调整，重新显示后按可见窗格重新测量并更新目标尺寸。
- PTY 退出后会话从所属窗格和活动会话索引移除；窗格及分栏树保持不变。失败状态保留供用户辨认。
- 每项目会话默认标题按项目名称、CLI、序号生成；手动名称与生成标题区分，项目重命名只更新生成标题。
- 点击项目不替换共享工作区，而是更新目标项目并高亮相应窗格；聚焦会话则同步当前项目上下文。
- 右侧面板在宽窗口默认展开，窄窗口自动收起；启动/恢复目标始终明确显示项目名称。
- PTY 不变量、退出与托盘行为延续 M0/M1；M2 不持久化当前分栏树，布局持久化归属 M3。
- 自定义全局/项目参数及模型选择全部从当前 UI 和启动链移除；已有数据库记录不删除但不执行，旧 JSON 配置导入忽略它们，新导出不包含它们。

## 测试与门禁计划

### 本次新增范围的执行顺序

1. **状态模型与窗格内拖放：** 扩展递归布局操作与单归属不变量，拖动同一 session ID 到已有窗格；覆盖空 pane、同 pane 拖放、连续拖动和拖放目标失效。
2. **PTY 输出交接协议：** 在 Rust service 增加单所有者窗口绑定、有界输出重放、暂停水位和一次性交接记录；为并发输出、确认序号、回滚和会话退出添加单元测试。
3. **Tauri 独立窗口：** 增加一次性交接命令和创建窗口能力；独立窗以 session ID 加令牌启动，从 Rust 验证并读取元数据；恢复 xterm 快照后接管输入/尺寸，失败时取消交接并恢复原订阅。
4. **回收与跨窗口拖动：** 独立窗关闭或显式返回时完成反向交接并加入当前聚焦 pane；尝试从独立窗拖至目标 pane，验证失败时显式返回操作仍可用。
5. **代码审查与最终门禁：** 对照单 PTY、窗口关闭、TUI 连续性、资源上限及平台能力进行审查，修复后复审；重跑完整自动检查和 Windows 手工矩阵，未通过项不得标记 M2 完成。

- 文件边界：布局操作位于 `src/lib/ptyWorkspaceLayout.ts`；终端快照与交接状态位于 `src/components/PtyTerminal.tsx`、`src/components/PtyWorkspace.tsx`；窗口入口和事件路由位于 `src/App.tsx` 与 Tauri commands/services；窗口能力在 Tauri capability 配置中限于主窗口和本功能创建的终端窗口；交互文案及样式分别更新 `src/i18n/locales/` 和 `src/styles.css`。
- 输出交接的数据必须是进程内短暂数据，不写入 SQLite、配置导出或日志；一次性交接失败/超时应恢复源 channel，限制输出重放缓存上限并测试上限边界。
