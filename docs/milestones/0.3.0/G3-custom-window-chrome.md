# G3：统一自定义窗口标题栏

**状态：** 实施中；核心自动门禁已通过，待 G2 前置验收及 G3 Windows 窗口实机验收
**所属版本：** 0.3.0
**依赖：** M2、M3 已验收；G2 Windows 实机验收是 G3 最终验收前置条件。本次按用户要求，G3 实施与 G2 手工验收并行推进。
**后续依赖：** M4、M5

## 目标

将 CLI Launchpad 的主工作区和独立终端窗口统一为应用绘制的自定义标题栏，减少原生标题栏和重复品牌区域占用的空间。主工作区顶部栏固定承载应用级操作；项目侧栏只呈现项目管理；独立终端窗口在同一标题栏中保留 CLI 会话标题与返回工作区入口。

应用需要接管 Windows/Linux 窗口的最小化、最大化/还原、关闭、标题栏拖动和双击最大化/还原。macOS 保留原生红黄绿交通灯，并使用原生标题栏覆盖模式承载统一的应用标题栏内容。自定义窗口装饰不得改变 PTY 归属、输入输出、尺寸更新、窗格布局、关闭生命周期和窗口状态恢复。

## 已确认的交互与平台契约

### 窗口范围

- 主工作区窗口和承载单个 PTY 的独立终端窗口都使用自定义标题栏样式。
- 窗口按钮、标题栏高度、间距、背景与交互反馈在应用窗口间保持一致；macOS 原生交通灯是有意保留的平台差异。
- 独立终端窗口标题栏继续显示 CLI 图标、会话标题和“返回工作区”；不加入项目区、布局保存/应用或分栏操作。
- 新建的辅助/系统窗口若未来出现，必须显式选择原生或自定义装饰，不隐式继承主工作区的交互策略。

### 平台窗口策略

| 平台    | 原生窗口装饰                                        | 应用负责                                                                 | 原生保留                                       |
| ------- | --------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------- |
| Windows | 关闭主窗口与独立终端窗口装饰                        | 最小化、最大化/还原、关闭、拖动、标题栏双击、必要的边缘缩放命中区        | 系统窗口管理器仍负责最终窗口几何与显示器工作区 |
| Linux   | 关闭主窗口与独立终端窗口装饰                        | 最小化、最大化/还原、关闭、拖动、标题栏双击；验证窗口管理器/Wayland 行为 | 桌面窗口管理器与 Wayland/X11 的能力边界        |
| macOS   | 保留原生装饰，使用 overlay 标题栏并隐藏系统标题文字 | 绘制相同的应用级标题栏内容；标题栏空白区域支持拖动与双击缩放/还原        | 原生红黄绿交通灯及其可访问性/系统行为          |

- Windows/Linux 主窗口和独立窗口都必须逐窗设置装饰策略，避免动态创建的 `WebviewWindow` 因默认值而重新出现系统标题栏。
- macOS 为交通灯预留系统安全空间；顶部栏内容不得覆盖、遮挡或截获交通灯点击。
- 本里程碑的实机验收基线为 Windows。macOS/Linux 配置和编译检查属于 G3 自动门禁，真实窗口交互在 M5 跨平台验收。

### 主工作区标题栏

- 移除左侧项目区顶部的产品 Logo 与软件名称占位。
- 应用级标题栏右侧固定放置上下文侧栏收起/展开、布局保存/应用等全局工作区操作，以及平台要求的窗口控制按钮。
- 按钮不跟随当前聚焦窗格移动，不覆盖窗格标题、分栏按钮或终端拖放目标；窄窗口下按已定义优先级收纳或折叠，不遮挡交互。
- 标题栏剩余的非交互空白区域作为窗口拖动区域；按钮、输入控件、弹层锚点和其他可交互区域不得触发拖动。

### 独立终端标题栏

- 保留 CLI 图标、项目/CLI/序号会话标题和“返回工作区”；最小化、最大化/还原与关闭入口置于右侧。
- 标题栏空白区用于移动独立窗口；双击空白标题区切换最大化/还原。
- 会话标题仍是跨窗口拖放会话的专用 HTML 拖动源，可拖入主工作区目标窗格。该拖动不得同时启动操作系统窗口拖动。
- “返回工作区”继续将同一个 PTY 交还主工作区当前激活窗格，不终止、复制或重启 PTY。

### 窗口控制和生命周期

- 主窗口自定义关闭按钮必须触发现有 `CloseRequested` 策略：按设置隐藏到托盘或退出；退出时仍执行活动 PTY 确认与进程树清理。
- 独立窗口自定义关闭按钮必须触发现有关闭拦截与交接状态机：运行中会话返回工作区，已结束会话完成清理；失败时保留现有重试/错误行为，不产生僵尸窗口。
- 自定义标题栏按钮调用 Tauri 窗口 API，不以 DOM 隐藏/卸载伪装最小化、最大化或关闭。
- 最大化/还原图标及可访问名称跟随窗口真实状态更新；关闭、托盘隐藏、最大化和显示器变化继续与当前窗口状态持久化规则兼容。
- 去掉原生装饰后若平台不再提供可用边缘缩放命中区，必须通过受控的窗口缩放拖动区补齐；不可牺牲主窗口和独立窗口的调整大小能力。

## 范围

### 本里程碑包含

- 为主工作区和动态创建的独立 PTY 窗口落实逐平台窗口装饰配置。
- 建立可复用的应用窗口标题栏 UI/窗口操作封装，支持主窗口和独立窗口的内容差异。
- 将主工作区全局操作移入标题栏，移除左侧品牌标题行。
- 将独立窗口现有头部整合为自定义标题栏，并加入窗口控制按钮。
- 实现平台窗口按钮、标题栏拖动、双击最大化/还原和必要的缩放命中区。
- 保留 macOS 原生交通灯，并安全避让交通灯区域。
- 补充组件/纯逻辑测试、文档、Windows 手工验收清单与实测记录。

### 本里程碑不包含

- 不改变 CLI/PTY/布局对象模型、PTY 生命周期、会话拖动与窗格分栏规则。
- 不改变应用关闭行为设置、托盘菜单、活动 PTY 退出确认或窗口状态数据格式。
- 不改写独立窗口“返回工作区”的目标选择和失败恢复策略。
- 不重绘系统菜单、任务栏/Dock、系统贴靠面板或操作系统交通灯。
- 不将标题栏个性化、用户自定义按钮或可配置工具栏纳入设置。
- 不要求 G3 阶段完成 macOS/Linux 实机认证；对应设备实测留给 M5。

## 分阶段实施计划

### 阶段 0：基线与平台交互原型

1. 核对主窗口和独立窗口创建路径、`tauri.conf.json` 与运行时 `WebviewWindowBuilder` 的装饰默认值、窗口状态插件恢复流程。
2. 记录主窗口关闭/托盘/活动 PTY 保护路径，以及独立窗口关闭/返回/自然退出状态机的调用入口。
3. 用小型可丢弃原型验证 Windows 无装饰窗口的拖动、双击最大化/还原、最大化状态事件与边缘缩放；验证 macOS overlay 配置与交通灯避让实现方式。
4. 冻结主窗口和独立窗口的标题栏信息结构、点击/拖动命中区、窄宽度折叠顺序及无障碍名称。

**验收：** 原型证实无需改变 PTY 生命周期即可控制两类窗口；确认每个平台具体窗口 API、配置和限制；已记录失败回退行为。发现无法稳定实现的操作时先调整方案，不进入全面实现。

### 阶段 1：窗口策略和操作边界

1. 在 Tauri 配置中为主窗口应用平台策略；确保 macOS 采用原生 overlay/隐藏系统标题，Windows/Linux 采用应用自绘装饰。
2. 在独立窗口动态创建处显式应用同一平台策略，避免依赖 builder 默认值。
3. 建立封装后的窗口操作入口，提供最小化、最大化状态读取/切换、关闭、开始拖动和开始边缘缩放；不可用平台能力返回可处理错误。
4. 明确仅主窗口和独立 PTY 窗口适用；保留现有标签、窗口状态持久化和单实例行为。

**验收：** 两种窗口在目标平台读取到预期装饰策略；调用封装可以正确定位当前 Webview；操作错误不会导致 UI 崩溃；macOS 原生交通灯未被隐藏。

### 阶段 2：统一标题栏 UI

1. 新增复用标题栏组件与紧凑、主题适配的样式；主窗口和独立窗口通过明确变体提供各自内容。
2. 主窗口移除 Sidebar 品牌标题行；将侧栏按钮、工作区布局保存/应用放到应用标题栏右侧固定区域。
3. 独立窗口将现有终端头部改为同款标题栏，保留 CLI 图标、标题、返回工作区和会话跨窗拖放源。
4. Windows/Linux 展示应用绘制的最小化、最大化/还原、关闭按钮；macOS 隐藏重复绘制的三种窗口控制按钮并避让原生交通灯。
5. 为按钮提供 tooltip、键盘焦点、无障碍名称、禁用/错误反馈和深浅主题状态。

**验收：** 两种窗口视觉一致且内容符合各自用途；原有右侧面板与布局操作均可达；主项目区不再显示 Logo/软件名；标题、按钮和弹层无重叠或被裁切。

### 阶段 3：窗口手势、调整大小与交接兼容

1. 对标题栏明确划分空白窗口拖动区、普通按钮区、macOS 交通灯避让区和独立会话 HTML 拖动源。
2. 在 Win/Linux 的空白区接入窗口拖动；标题栏空白区双击切换最大化/还原，单击按钮执行最小化/最大化/关闭。
3. 在 macOS 原生 overlay 标题栏内验证拖动和双击行为；保留交通灯的系统点击行为，应用内容区不吞掉点击。
4. 为去掉装饰后失去的 resize 边缘补足平台支持的缩放拖动区，并约束最小尺寸、边角和 DPI 缩放。
5. 验证独立会话标题拖回主工作区时只发起会话交接，不移动独立窗口；返回、关闭和自然退出仍由现有交接/退出状态机收敛。

**验收：** 窗口拖动不误触按钮；拖会话不移动窗口；双击只在空白标题栏生效；窗口可用鼠标缩放；所有交接行为不会复制 PTY、产生重复标签、丢失输入或遗留僵尸窗口。

### 阶段 4：集成、回归和文档同步

1. 验证最大化/还原状态事件，标题栏图标和可访问名称与窗口实际状态一致。
2. 验证应用冷启动、托盘唤起、窗口隐藏/显示、关闭策略、活动 PTY 退出保护和跨屏恢复。
3. 覆盖窄窗口、左右/上下分栏、右侧上下文面板展开/折叠、布局弹层和终端标签拥挤场景。
4. 更新产品需求、架构、UI 设计、路线图、里程碑索引和 G3 实施记录。

**验收：** 标题栏行为不改变已验收的窗口几何、托盘、工作区布局和 PTY 生命周期；文档与实现一致。

### 阶段 5：代码审查、最终门禁与用户验收

1. 按本文件逐项审查配置覆盖、当前窗口选择、按钮状态订阅、拖动命中区、关闭事件和独立 PTY 交接。
2. 修复审查发现并复审；复审中出现新问题时继续闭环。
3. 重跑全部自动门禁，并启动 Windows 开发版提供手工验收。
4. 记录 Windows 用户验收结果；未验收前不得把 G3 标为完成或声明 M4 可关闭。
5. 仅暂存 G3 相关文档与代码，按项目提交约定提交。

## 测试覆盖与门禁

### 自动门禁

- [ ] Tauri 主窗口配置通过 schema/构建校验；平台配置中的 `decorations`、macOS `titleBarStyle`、隐藏标题和交通灯位置值合法。
- [ ] 动态独立窗口创建逻辑有测试或可审查断言，证明它显式应用平台装饰策略，不依赖默认值。
- [ ] 窗口操作封装覆盖 minimize、toggle maximize、close、drag、resize 的平台分支、无窗口和 API 失败路径。
- [ ] 窗口最大化事件订阅可清理；组件卸载/窗口切换不会保留重复监听器。
- [ ] 标题栏单击、双击、键盘触发按钮及拖放判别逻辑有单元/组件测试；独立会话拖放仍使用现有 PTY 拖放数据契约。
- [ ] 关闭按钮复用现有 `CloseRequested` 路径：主窗口托盘/退出/活动 PTY 保护测试通过；独立窗口仍执行运行中交还、已结束关闭和失败恢复。
- [ ] `pnpm exec prettier --check`（覆盖本里程碑修改的 TS/TSX/CSS/Markdown/JSON）、`pnpm run test`、`pnpm run build` 通过；Rust `cargo fmt --check --manifest-path src-tauri/Cargo.toml`、`cargo test --manifest-path src-tauri/Cargo.toml`、`cargo check --manifest-path src-tauri/Cargo.toml` 通过。
- [ ] `git diff --check` 通过；前端与 Rust 无由本次改动新增的错误或未处理警告。
- [ ] Windows CI/本机构建通过；macOS 与 Linux 至少完成配置/编译门禁，记录未进行真机窗口行为验收的限制。

### Windows 手工验收

- [ ] 主窗口无原生标题栏；项目区顶部品牌行已移除；侧栏切换、布局保存/应用入口位于标题栏固定位置。
- [ ] 主窗口拖动标题栏空白区域移动窗口；双击空白区最大化，再双击还原；按钮和弹层区域不会启动拖动。
- [ ] 最小化后从任务栏/托盘恢复正常；最大化、还原、退出的图标状态同步准确。
- [ ] 主窗口在四边和四角可以调整大小；多显示器/DPI 下无无法命中的窄边、跳动或窗口跑出屏幕。
- [ ] 点主窗口关闭时按“最小化到托盘/退出”设置生效；存在活动 PTY 时仍出现确认，取消后 PTY 可继续输入。
- [ ] 独立终端窗口无原生标题栏，样式与主窗口一致；显示 CLI 图标、会话名、返回工作区和自定义窗口按钮。
- [ ] 独立窗口标题栏空白区域可移动窗口，双击可最大化/还原，窗口边缘可缩放。
- [ ] 将独立终端标题拖入主工作区指定窗格，确认移动的是同一 PTY，独立窗口收尾正确、目标窗格可输入。
- [ ] 点击独立窗口“返回工作区”及自定义关闭按钮，运行中会话都返回当前激活窗格；pty 退出后独立窗口自动收敛；无重复标签、错误计数或僵尸窗口。
- [ ] 独立窗口标题拖动会话时不移动窗口；窗口移动时不触发会话交接。
- [ ] 主/独立窗口在暗色、浅色主题下按钮对比、悬浮态和标题可读；窄窗口时按钮不会覆盖分栏入口或终端标签。
- [ ] 应用重启后窗口尺寸/位置/最大化状态按既有边界保护恢复；自定义标题栏没有使窗口状态插件保存错误几何。

### macOS/Linux 后续手工验收（M5）

- [ ] macOS 主窗口与独立终端窗口保留原生红黄绿交通灯，点击行为正常；应用标题栏内容不覆盖系统控制。
- [ ] macOS overlay 的空白拖动区、双击缩放/还原和深浅主题通过 Apple Silicon/Intel 可用设备验证；记录系统版本差异。
- [ ] Linux 主窗口及独立窗口在受支持桌面环境中无原生标题栏，最小化/最大化/关闭、拖动、双击和缩放行为符合窗口管理器能力；单独记录 X11/Wayland 差异。

## 风险与处理

| 风险                                                              | 处理                                                                                                     |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `decorations: false` 同时移除平台原生按钮和边缘 resize hit target | 先做阶段 0 原型；按平台补充 Tauri resize dragging 区域，自动门禁和手工验收都覆盖四边/四角。              |
| 独立终端标题同时承担会话拖放和窗口拖动                            | 使用互不重叠的 HTML 会话拖动源与空白窗口拖动区；手势开始后不转换为另一种动作。                           |
| 自定义主窗口关闭绕过托盘/PTY 确认策略                             | 关闭按钮只调用当前窗口 close API，并测试 Rust `CloseRequested` 与 `RunEvent::ExitRequested` 的完整链路。 |
| macOS overlay 高度/安全区随系统版本变化                           | 交通灯位置采用平台参数，UI 留安全内边距；在 M5 按支持系统实机验证，不以 Windows 几何硬编码。             |
| Linux Wayland 窗口管理器限制程序化拖动/最大化                     | 使用受支持的 Tauri 窗口接口，按桌面环境记录差异；不提供伪成功反馈。                                      |
| 子窗口配置遗漏而意外保留原生标题栏                                | 动态 builder 必须显式配置；自动化检查主窗口和独立窗口配置入口。                                          |
| 窗口状态插件与无装饰窗口产生恢复差异                              | 重启、托盘唤醒、最大化、换屏和 DPI 场景列为必过手工门禁。                                                |
