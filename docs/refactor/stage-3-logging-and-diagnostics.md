# 阶段 3：日志与诊断导出

## 目标

让安装、启动、迁移、备份与外部检测问题可追溯，同时控制隐私泄漏和
磁盘增长。

## 日志路径与保留

```text
~/.cli-launchpad/logs/cli-launchpad.log
```

- 使用官方 `tauri-plugin-log` 的自定义 `Folder` target。
- 单文件最大 2 MiB。
- 启动时清理过期轮转文件，最多保留 10 个日志文件。

## 应记录的事件

| 领域     | 事件                                          |
| -------- | --------------------------------------------- |
| 启动     | 应用版本、存储目录初始化结果、旧数据迁移结果  |
| 数据库   | schema 版本、健康检查结果、迁移/备份/恢复结果 |
| CLI 状态 | 工具名、是否找到、检测耗时、失败类别          |
| 安装更新 | 工具名、动作、成功/失败、退出状态             |
| 启动会话 | 目录 id、工具名、动作、成功/失败              |
| 配置交换 | 导入/导出成功或失败，不记录配置正文           |

## 脱敏边界

日志禁止写入：

- 用户填写的完整工具参数。
- 命令预览完整文本。
- CLI 会话标题正文或源文件内容。
- 可能包含 token、API key 或认证信息的原始 stdout/stderr。

安装原始输出仍仅在用户主动执行后的当前 UI 中展示；持久日志只记录
操作状态和错误类别。

## 具体改动

- 添加 `log` 与 `tauri-plugin-log` 依赖。
- 新增 `services/diagnostics_service.rs`：
  - 日志目录准备和历史文件清理。
  - 生成诊断导出 JSON。
- 为关键 services 与 commands 添加结构化日志调用。
- 新增 `export_diagnostics_to_path` command。
- 设置页新增诊断导出入口，导出：
  - 应用版本和平台。
  - 存储目录状态。
  - 数据库 schema 版本。
  - 日志文件内容。

## 测试与验收

- 关键失败场景会生成可定位日志。
- 日志文件大小和数量受控。
- 诊断导出文件可读取且不包含工具参数或命令正文。
