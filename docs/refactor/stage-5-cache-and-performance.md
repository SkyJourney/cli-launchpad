# 阶段 5：缓存与性能治理

## 目标

将可重建且可能耗时的数据与业务数据库隔离，降低反复探测和扫描开销，
并让用户清楚地控制缓存内容。

## 缓存路径与删除语义

```text
~/.cli-launchpad/cache/cache.db
```

删除 `cache.db` 后，项目目录、启动参数、备份与日志必须不受影响；应用
在下一次查询时重新生成缓存。

## 缓存内容

| 缓存         | 来源         | TTL / 失效                          |
| ------------ | ------------ | ----------------------------------- |
| CLI 状态快照 | 可信路径解析 | 短 TTL；手动刷新强制绕过            |
| 最新版本     | npm registry | 30 分钟；网络失败可回退最近成功结果 |

会话标题摘要可能包含用户工作内容，因此不持久写入应用缓存；详情页
每次查询直接从 Claude/Codex 的本地事实来源读取。

## 正确性边界

- 缓存只用于列表展示与状态加速。
- 真正启动 CLI 时仍实时解析可执行路径。
- 真正恢复会话时由应用重新确认 session id 属于当前目录后再交给目标 CLI。
- 缓存数据库损坏时直接重建，不影响业务数据库启动。

## 具体改动

- 新增 `db/cache_connection.rs` 与 `services/cache_service.rs`。
- 注册独立 `CacheDb` 状态。
- 为状态、版本 commands 接入缓存和强制刷新参数。
- 新增 commands：
  - `get_cache_stats`
  - `clear_cache`
- 设置页增加缓存条目数、大小、最近写入时间与清除操作。
- 详情页增加会话手动刷新入口。

## 测试与验收

- 删除或损坏缓存数据库后可自动重建。
- 手动刷新不读取旧缓存。
- 缓存命中减少状态和版本查询工作；会话读取保持实时且不持久保存摘要。
- 清除缓存后 UI 能正确重新加载。
