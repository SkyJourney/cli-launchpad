# 阶段 5：缓存与性能治理

## 目标

将可重建且可能耗时的数据与业务数据库隔离，降低反复探测和扫描开销，
并让用户清楚地控制缓存内容。

## 缓存路径与删除语义

```text
~/.cli-launchpad/cache/cache.db
```

删除 `cache.db` 后，项目目录、启动参数、备份与日志必须不受影响；应用
在下一次查询时重新生成缓存。

## 缓存内容

| 缓存 | 来源 | TTL / 失效 |
| --- | --- | --- |
| CLI 状态快照 | `where.exe` 与 `--version` | 短 TTL；手动刷新强制绕过 |
| 最新版本 | npm registry | 30 分钟；网络失败可回退到标注时间的旧值 |
| 会话索引 | Claude/Codex 本地 JSONL | 短 TTL；手动刷新或清除后重建 |

会话索引包含标题摘要，属于可能包含用户工作内容的本地缓存。因此 UI
必须提供清理能力，文档必须明确其内容和来源。

## 正确性边界

- 缓存只用于列表展示与状态加速。
- 真正启动 CLI 时仍实时解析可执行路径。
- 真正恢复会话时仍由目标 CLI 验证 session id。
- 缓存数据库损坏时直接重建，不影响业务数据库启动。

## 具体改动

- 新增 `db/cache_connection.rs` 与 `services/cache_service.rs`。
- 注册独立 `CacheDb` 状态。
- 为状态、版本与会话 commands 接入缓存和强制刷新参数。
- 新增 commands：
  - `get_cache_stats`
  - `clear_cache`
- 设置页增加缓存大小、刷新时间与清除操作。
- 详情页增加会话手动刷新入口。

## 测试与验收

- 删除或损坏缓存数据库后可自动重建。
- 手动刷新不读取旧缓存。
- 缓存命中减少后台命令调用和会话正文解析。
- 清除缓存后 UI 能正确重新加载。
