# GUI 设计

CLI Launchpad 的界面设计参考 cc-switch 的卡片式项目管理思路：项目为一等公民，会话历史可视化，启动即恢复。整体采用多视图结构而非弹窗，所有视图共享左侧固定侧边栏。

## 设计原则

- 视图优于弹窗：主要操作在独立视图中完成，保持上下文连续。
- 直接启动为常态：点击工具即启动，命令预览作为可折叠的辅助能力。
- 全局 CLI 状态驱动 UI：CLI 是否可用是应用级状态，统一下发到所有视图，缺失的工具在任何位置都呈灰色禁用。
- 三个 CLI 的会话历史分 Tab 展示，不混在同一列表中。

## 全局 CLI 状态

应用在 Tauri 启动时检测三个 CLI，并把结果作为全局状态贯穿所有视图。该状态可手动刷新（设置页"重新检测"）。

```text
cli_status
  claude:  { status, path, version, latest_version, resolved_command }
  codex:   { status, path, version, latest_version, resolved_command }
  agy:     { status, path, version, latest_version, resolved_command }
```

状态对应的 UI 表现（启动一律走解析出的**完整路径**，因此不再区分 PATH 是否可见）：

| 状态      | 徽章 | 含义                         | UI 行为                                      |
| --------- | ---- | ---------------------------- | -------------------------------------------- |
| available | 绿色 | 在 PATH 或已知目录找到全路径 | 启动按钮可用，参数可编辑                     |
| missing   | 灰色 | 未检测到                     | 启动按钮和参数编辑器禁用，引导前往设置页安装 |

## 视图结构

```text
┌──────────────────────────────────────────────┐
│  侧边栏（固定）  │  主内容区（按视图切换）       │
└──────────────────────────────────────────────┘

View A  项目主页（默认，卡片网格）
View B  项目详情（会话历史 Tab + 直接启动）
View C  项目参数编辑
View D  设置（CLI 状态/版本更新、启动方式、关闭窗口行为、工具全局参数、配置备份）
View E  执行任务（任务状态、实时日志、历史日志与终止操作）
View F  关于（软件信息与版本）
```

侧边栏导航：项目 / 执行任务 / 设置 / 关于。“执行任务”在有运行中任务时显示数量徽章。执行任务、设置、关于为顶层视图（无需顶部返回，靠侧边栏切换）；详情、编辑为项目上下文内的层级，保留返回。整卡片可点击进入详情，徽章和操作按钮除外。

## View A：项目主页

卡片网格展示所有目录。每张卡片显示：项目名、路径、最近使用时间、三个 CLI 的状态徽章。

```text
┌──────────────────┐
│ ★ cli-launchpad  │   ★ 表示置顶
│ C:\Projects\...  │
│ 5分钟前          │
│ ✅[C] ✅[X] ❌[A] │   徽章颜色来自全局 CLI 状态
└──────────────────┘
```

交互：

- 点击卡片主体 → View B。
- 点击状态徽章（仅 available）→ 直接在该目录启动对应 CLI。
- 右键 / 三点菜单 → 置顶、编辑参数、移除目录。
- 顶部工具栏：添加目录、排序、搜索。

## View B：项目详情

顶部显示项目名和路径，右上角"编辑参数"入口。主体是三个 CLI 的会话历史 Tab，每个 Tab 内有一键启动按钮和该 CLI 的历史会话列表。

```text
┌──────────────┬──────────────┬────────────────┐
│ 🤖 Claude ✅ │  🧩 Codex ✅ │  🚀 Agy ❌     │   Tab 颜色来自全局状态
└──────────────┴──────────────┴────────────────┘

▶ [启动 Claude Code]          ← 一键直接启动

历史会话
─────────────────────────────────────────────
⌚ 5分钟前   "实现 launch service"   [✎] [▶ 恢复]
⌚ 昨天      "修复 PowerShell 转义"   [✎] [▶ 恢复]
                         [更多]

▾ 命令预览                              [📋 复制]
wt.exe new-tab -d "..." pwsh.exe ...
```

Tab 行为：

- available 的 Tab 正常显示启动按钮和会话列表。
- missing 的 Tab 灰色不可点击。
- 每个 CLI 首次展示最新 10 条，点击“更多”追加 10 条；切换 Tab 保留各自已加载页数。
- 每条会话可设置本地别名；别名存在时标记为“自定义标题”，可恢复 CLI 原始标题。

命令预览：

- 默认折叠，点击展开。
- 复制按钮始终可见。
- 启动是常态，预览仅供查看和复制，不作为启动前的强制确认步骤。

## View C：项目参数编辑

按 CLI 分区编辑该项目的工具参数。每个分区显示该 CLI 的全局参数（只读展示）、启动模型和项目级附加参数（可编辑）。

```text
🤖 Claude Code                    ✅ 已安装
模型:      [Opus（最新版本） ▼] [或手动输入模型名]
附加参数:  [____________________]

🧩 Codex                          ✅ 已安装
模型:      [GPT-5.6-Sol       ▼] [或手动输入部署名]
附加参数:  [____________________]

🚀 Antigravity                    ✅ 已安装
模型:      [Gemini …          ▼] [或手动输入模型名]
附加参数:  [____________________]
```

- missing 的 CLI 分区整体灰色禁用。
- 项目级参数保存到 SQLite `directory_tool_args`。
- 三项 CLI 均支持目录选择和**手动输入**（兼容第三方模型或部署名），与“附加参数”中的 `--model` 是同一字符串的两个视图。
- Claude 目录使用官方稳定模型别名；Codex 通过 App Server `model/list`、Antigravity 通过 `agy models` 动态读取，并使用 10 分钟缓存和失败时旧缓存回退。
- 全局参数与项目级参数分离：全局参数在设置页维护（只读展示于此），项目级在此覆盖/追加。
- 启动时合并参数：项目级出现的 flag 会覆盖全局同名 flag（连同其值），避免重复参数导致启动失败。

## View D：设置

主要区块：CLI 状态与版本更新、启动方式、关闭窗口行为、工具全局参数、配置备份。

```text
CLI 状态                              [🔄 重新检测]
─────────────────────────────────────────────
🤖 Claude Code   [已安装]  路径: ~/.local/bin/claude
当前: 1.7.0   最新: 1.8.2   有更新   [▶ 更新]

🧩 Codex         [已安装]  当前: 0.1.0   最新: 0.1.0

🚀 Antigravity   [未检测到]                 [▶ 一键安装]

启动方式
(•) 自动选择（推荐）
当前平台终端
  ( ) 系统终端或默认 Profile       [默认] [推荐]
  ( ) 其他已检测终端/Profile       [原生]
  ( ) 其他已检测终端              [原生]

关闭窗口行为
(•) 关闭后保持后台运行   ( ) 退出应用
通过 Windows 托盘或 macOS 菜单栏/Dock 重新显示主界面

工具全局参数
Claude:  [____________________]
Codex:   [____________________]
Antigravity: [________________]            [保存全局参数]

配置备份
[导出到文件]   [从文件导入]
```

- 已安装且有新版：显示"更新"按钮，执行对应 CLI 的官方更新命令。
- 未安装：显示"一键安装"按钮，复用安装流程（见 tooling-and-installation.md）。
- 更新和安装都遵循同一原则：先预览命令、用户确认、输出日志、完成后重新检测。
- 用户确认后关闭确认浮层并创建后台任务，执行状态与实时日志转到“执行任务”视图展示。
- 启动方式列表来自 Rust 平台探测结果，不由 React 自行判断操作系统。Windows 展示 Windows Terminal Profiles 与独立 Shell；macOS 展示 Terminal.app，以及已检测到的 iTerm2、Ghostty、WezTerm 和 kitty。
- macOS 当前支持的五款终端均标记为“原生”。
- 设置页按真实接口说明启动方式：Terminal.app 与 iTerm2 使用一次性、自删除的 `.command`；Ghostty 使用 AppleScript 原生窗口；WezTerm 与 kitty 使用包内 CLI，kitty 额外保留命令退出后的窗口。
- 自动模式在 Windows 优先使用 Windows Terminal 默认 Profile，在 macOS 固定使用 Terminal.app；第三方终端只响应显式选择。命令预览按平台展示 Profile 保留级别、终端启动接口、临时载荷说明和失败回退链。
- 关闭窗口行为默认是保持后台运行；用户选择退出应用后，关闭主窗口即结束进程。Windows 托盘和 macOS 菜单栏菜单均提供显示主界面和退出入口，macOS 点击 Dock 图标也能恢复窗口。
- 配置备份通过系统文件对话框导出/导入 JSON（plugin-dialog），导入按目录路径合并。

## View F：关于

- 使用应用 Logo 展示品牌和版本；项目仓库入口使用 LobeHub 实心 GitHub Mark，固定在侧边栏左下角。
- 软件信息卡片优先展示三项受支持 CLI；不展示作者、仓库 URL、主命令或实现技术栈。
- 软件信息与开源许可使用两个独立全宽卡片，随工作区宽度响应式伸展。
- 许可卡片展示应用 MIT License 与两套内置字体的 SIL OFL 1.1，并允许展开查看随安装包内置的许可证全文。

## View E：执行任务

主内容区采用任务列表与日志详情双栏布局。任务列表显示工具、安装或更新类型、
开始时间和状态；选择任务后，右侧按输出顺序展示 `stdout`、`stderr` 和系统消息。

```text
执行任务                                      [清理全部历史]
┌──────────────────┬────────────────────────────────────┐
│ Agy 更新  执行中  │ C:\...\agy.exe update             │
│ Codex 更新  成功  │ [stdout] Checking for updates...   │
│ Claude 更新  失败 │ [stderr] ...                       │
│                  │                         [终止任务] │
└──────────────────┴────────────────────────────────────┘
```

- 状态分为准备中、执行中、正在终止、执行成功、执行失败、已取消、已超时和意外中断。
- 进入视图后实时跟随新增日志；查看历史任务时不强制跳到底部。
- 执行中任务提供“终止任务”，并警告更新中断可能导致 CLI 需要重新安装。
- 只允许清理已结束任务；清理单条或全部历史都需要确认。
- 日志超过 1 MiB 时显示“后续日志未保存”的截断提示；默认保留最近 50 个任务。

## 会话历史数据源

会话历史从各 CLI 的本地存储读取，按公开资料核验后的路径如下：

| CLI         | 会话事实来源                                              | 是否可列出历史 | 恢复命令                       |
| ----------- | --------------------------------------------------------- | -------------- | ------------------------------ |
| Claude Code | `sessions-index.json` 与项目目录内 `<uuid>.jsonl`         | 可以           | `claude --resume <session-id>` |
| Codex       | App Server `thread/list`，失败时回退 `~/.codex/sessions/` | 可以           | `codex resume <session-id>`    |
| Antigravity | 本机 `conversation_summaries.db` 与 conversation metadata | 可以           | `agy --conversation=<uuid>`    |

说明：

- Claude Code：优先使用会话索引中的 `summary`/`firstPrompt`，再回退到 JSONL 首条用户消息。
- Codex：优先读取 App Server 的 `name`/`preview`，失败时回退到 rollout JSONL。
- Antigravity：只读本机 SQLite 摘要库与 metadata，并按 workspace URI 精确匹配项目。

当前实现按需实时读取，不建立原始会话缓存表。用户手动设置别名时才在业务 SQLite 中写入一条 `tool_key + session_id` 关联；删除别名即恢复原始标题。

## 状态管理

前端引入轻量全局状态（如 Zustand）管理：

- 全局 CLI 状态。
- 当前视图和选中目录。
- 目录列表、会话索引等从 Tauri commands 拉取的数据缓存。

设备本地 UI 偏好（窗口尺寸、上次选中目录、主题）后续放在 JSON 或 Tauri store，不进 SQLite。
