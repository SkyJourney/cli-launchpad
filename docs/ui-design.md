# GUI 设计

CLI Launchpad 的界面设计参考 cc-switch 的卡片式项目管理思路：项目为一等公民，会话历史可视化，启动即恢复。整体采用多视图结构而非弹窗，所有视图共享左侧固定侧边栏。

## 设计原则

- 视图优于弹窗：主要操作在独立视图中完成，保持上下文连续。
- 直接启动为常态：点击工具即启动，命令预览作为可折叠的辅助能力。
- 全局 CLI 状态驱动 UI：CLI 是否可用是应用级状态，统一下发到所有视图，缺失的工具在任何位置都呈灰色禁用。
- 三个 CLI 的会话历史分 Tab 展示，不混在同一列表中。

## 全局 CLI 状态

应用在 Tauri 启动时检测三个 CLI，并把结果作为全局状态贯穿所有视图。该状态可手动刷新（设置页"重新检测"）。

```text
cli_status
  claude:  { status, path, version, latest_version, resolved_command }
  codex:   { status, path, version, latest_version, resolved_command }
  agy:     { status, path, version, latest_version, resolved_command }
```

状态对应的 UI 表现（启动一律走解析出的**完整路径**，因此不再区分 PATH 是否可见）：

| 状态      | 徽章 | 含义                         | UI 行为                                      |
| --------- | ---- | ---------------------------- | -------------------------------------------- |
| available | 绿色 | 在 PATH 或已知目录找到全路径 | 启动按钮可用，参数可编辑                     |
| missing   | 灰色 | 未检测到                     | 启动按钮和参数编辑器禁用，引导前往设置页安装 |

## 视图结构

```text
┌──────────────────────────────────────────────┐
│  侧边栏（固定）  │  主内容区（按视图切换）       │
└──────────────────────────────────────────────┘

View A  项目主页（默认，卡片网格）
View B  项目详情（会话历史 Tab + 直接启动）
View C  项目参数编辑
View D  设置（CLI 状态/版本更新、启动方式、关闭窗口行为、工具全局参数、配置备份）
View E  关于（软件信息与版本）
```

侧边栏导航：项目 / 设置 / 关于。设置、关于为顶层视图（无需顶部返回，靠侧边栏切换）；详情、编辑为项目上下文内的层级，保留返回。整卡片可点击进入详情，徽章和操作按钮除外。

## View A：项目主页

卡片网格展示所有目录。每张卡片显示：项目名、路径、最近使用时间、三个 CLI 的状态徽章。

```text
┌──────────────────┐
│ ★ cli-launchpad  │   ★ 表示置顶
│ C:\Projects\...  │
│ 5分钟前          │
│ ✅[C] ✅[X] ❌[A] │   徽章颜色来自全局 CLI 状态
└──────────────────┘
```

交互：

- 点击卡片主体 → View B。
- 点击状态徽章（仅 available）→ 直接在该目录启动对应 CLI。
- 右键 / 三点菜单 → 置顶、编辑参数、移除目录。
- 顶部工具栏：添加目录、排序、搜索。

## View B：项目详情

顶部显示项目名和路径，右上角"编辑参数"入口。主体是三个 CLI 的会话历史 Tab，每个 Tab 内有一键启动按钮和该 CLI 的历史会话列表。

```text
┌──────────────┬──────────────┬────────────────┐
│ 🤖 Claude ✅ │  🧩 Codex ✅ │  🚀 Agy ❌     │   Tab 颜色来自全局状态
└──────────────┴──────────────┴────────────────┘

▶ [启动 Claude Code]          ← 一键直接启动

历史会话 (3)
─────────────────────────────────────────────
⌚ 5分钟前   "实现 launch service"   [▶ 恢复]
⌚ 昨天      "修复 PowerShell 转义"   [▶ 恢复]

▾ 命令预览                              [📋 复制]
wt.exe new-tab -d "..." pwsh.exe ...
```

Tab 行为：

- available 的 Tab 正常显示启动按钮和会话列表。
- missing 的 Tab 灰色不可点击。
- 不支持会话历史列表的 CLI（见下文）在 Tab 内显示提示文案，但仍提供一键启动。

命令预览：

- 默认折叠，点击展开。
- 复制按钮始终可见。
- 启动是常态，预览仅供查看和复制，不作为启动前的强制确认步骤。

## View C：项目参数编辑

按 CLI 分区编辑该项目的工具参数。每个分区显示该 CLI 的全局参数（只读展示）和项目级附加参数（可编辑）。Claude 区额外提供模型快捷选择。

```text
🤖 Claude Code                    ✅ 已安装
模型:      [claude-opus-4-7   ▼]
附加参数:  [____________________]

🧩 Codex                          ✅ 已安装
附加参数:  [____________________]

🚀 Antigravity                    ❌ 未安装
░░░░░░░░░░░░░░░  （禁用，前往设置安装）
```

- missing 的 CLI 分区整体灰色禁用。
- 项目级参数保存到 SQLite `directory_tool_args`。
- Claude 模型支持快捷选择和**手动输入**（兼容第三方模型），与"附加参数"中的 `--model` 是同一字符串的两个视图。
- 全局参数与项目级参数分离：全局参数在设置页维护（只读展示于此），项目级在此覆盖/追加。
- 启动时合并参数：项目级出现的 flag 会覆盖全局同名 flag（连同其值），避免重复参数导致启动失败。

## View D：设置

主要区块：CLI 状态与版本更新、启动方式、关闭窗口行为、工具全局参数、配置备份。

```text
CLI 状态                              [🔄 重新检测]
─────────────────────────────────────────────
🤖 Claude Code   [已安装]  路径: C:\...\claude.exe
当前: 1.7.0   最新: 1.8.2   有更新   [▶ 更新]

🧩 Codex         [已安装]  当前: 0.1.0   最新: 0.1.0

🚀 Antigravity   [未检测到]                 [▶ 一键安装]

启动方式
( ) Windows Terminal + PowerShell   ( ) PowerShell 窗口

关闭窗口行为
(•) 最小化到托盘   ( ) 退出应用
关闭到托盘后，双击托盘图标显示主界面

工具全局参数
Claude:  [____________________]
Codex:   [____________________]
Antigravity: [________________]            [保存全局参数]

配置备份
[导出到文件]   [从文件导入]
```

- 已安装且有新版：显示"更新"按钮，执行对应 CLI 的官方更新命令。
- 未安装：显示"一键安装"按钮，复用安装流程（见 tooling-and-installation.md）。
- 更新和安装都遵循同一原则：先预览命令、用户确认、输出日志、完成后重新检测。
- 启动方式决定终端/Shell（详见 architecture.md 的启动组合）。
- 关闭窗口行为默认是最小化到托盘；用户选择退出应用后，关闭主窗口即结束进程。托盘右键菜单始终提供显示主界面和退出入口。
- 配置备份通过系统文件对话框导出/导入 JSON（plugin-dialog），导入按目录路径合并。

## View E：关于

展示软件名、版本（Tauri `getVersion`）、技术栈、支持的 CLI 与命令。

## 会话历史数据源

会话历史从各 CLI 的本地存储读取，按公开资料核验后的路径如下：

| CLI         | 会话存储路径                                   | 是否可列出历史 | 恢复命令                       |
| ----------- | ---------------------------------------------- | -------------- | ------------------------------ |
| Claude Code | `~/.claude/projects/<slug>/<uuid>.jsonl`       | 可以           | `claude --resume <session-id>` |
| Codex       | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` | 可以           | `codex resume <session-id>`    |
| Antigravity | 官方未公开磁盘路径                             | 不可以         | `agy --conversation=<uuid>`    |

说明：

- Claude Code：每个项目目录对应一个 slug 目录，目录内每个 `.jsonl` 是一次会话，首条 user 消息作为标题。slug 是项目绝对路径的转换形式。
- Codex：rollout 文件按日期分层存储，文件内含 session 信息。可解析出标题、时间。
- Antigravity：官方文档未公开本地会话文件路径，只提供"按 conversation id 恢复"。因此 Agy 的会话 Tab 不展示历史列表，只显示"暂不支持历史列表，可直接启动新会话"，并保留一键启动。

当前实现为按需实时读取（只读首条消息与文件 mtime），未建缓存表；事实来源始终是各 CLI 的本地文件。

## 状态管理

前端引入轻量全局状态（如 Zustand）管理：

- 全局 CLI 状态。
- 当前视图和选中目录。
- 目录列表、会话索引等从 Tauri commands 拉取的数据缓存。

设备本地 UI 偏好（窗口尺寸、上次选中目录、主题）后续放在 JSON 或 Tauri store，不进 SQLite。
