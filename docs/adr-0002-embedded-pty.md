# ADR-0002：内置 PTY 与终端输出传输

**状态：** 已采纳（0.3.0 M1）
**日期：** 2026-09-27

## 背景

0.3.0 将 CLI 交互从系统外部终端迁入 Tauri 主窗口。实现需要统一管理 PTY、完整进程树和项目归属，同时在高频 TUI 输出下保持 WebView 响应。M0 已确定 PTY 不跨应用重启恢复、终端输出不进入数据库，托盘隐藏时进程继续运行，显式退出时先确认再结束全部托管进程。

## 决策

1. **继续使用 Tauri + React + Rust。** Rust service 是 PTY 和子进程生命周期的唯一所有者，React 只负责终端渲染与输入事件；不引入 Electron、服务端运行时或第二套 PTY 管理器。
2. **Rust PTY 后端使用 `portable-pty`。** 在 Windows 使用 ConPTY，在 macOS/Linux 使用系统 PTY。通过 `MasterPty` 创建读写端和同步尺寸，通过 `Child` 监控根进程退出。
3. **进程树隔离由本项目的平台 helper 负责。** Windows 将 PTY 子进程加入带 `KILL_ON_JOB_CLOSE` 的 Job Object；Unix 使用 PTY 进程组发送终止信号。`portable-pty` 的 child kill 仅作为根进程兜底，不替代平台进程树清理。会话的 PTY、child 和隔离句柄由同一 Rust 会话对象持有，关闭或应用退出时一并释放。
4. **前端使用 xterm.js 与 Fit addon。** xterm.js 只作为终端模拟器，不承担会话所有权或 CLI 状态判断。M1 在现有项目详情视图中承载单终端切片；大窗口、项目导航和多面板属于 M2/M3。
5. **输出使用 Tauri Channel，并加应用级确认回压。** Rust 按有界批次发送带序号的输出块；React 将块写入终端后确认已消费序号。未确认数据达到高水位时暂停读取 PTY，低于恢复水位后继续读取。每会话未确认数据具有固定上限；会话关闭时取消读写和监控任务，丢弃尚未发送的数据并释放通道。
6. **输入走独立 Tauri command。** 输入仅接受会话 ID 和原始文本/按键数据；尺寸由前端以列、行和像素尺寸提交，Rust 校验非零边界后执行 resize。输出通道和输入调用相互独立，避免输出拥塞阻塞键盘输入。
7. **启动参数继续复用结构化安全边界。** 只从内置 `ToolKey` 解析 `claude`、`codex`、`agy` 的完整可执行路径，复用全局与项目参数合并及工作目录校验逻辑；环境清理和 Windows 用户 PATH 合并继续适用于内置 PTY。PTY 启动失败明确报错，不静默回退到外部终端。
8. **SQLite 只持久化会话元数据。** 保存稳定会话 ID、项目 ID、工具、工作目录、状态、创建/结束时间及退出码；不保存终端输出、滚屏或密钥。应用启动时把旧运行态记录更新为已结束，绝不尝试接管旧进程。

## 进程生命周期与关闭

- 正常关闭单个 PTY 时只结束对应会话的进程树，并记录退出状态。
- Windows Job Object 的关闭策略确保应用异常结束时由操作系统清理托管子进程树；Unix 由应用正常退出钩子发送进程组终止信号，异常结束和平台实测结果作为跨平台发布门禁记录。
- 主窗口隐藏到托盘不触碰 PTY。
- 应用退出请求若有活动会话，先交由前端确认；取消则清除退出请求，确认后逐个终止进程树并退出。不能绕过确认直接退出。
- 项目删除前若存在活动 PTY，拒绝删除并给出明确错误，避免会话失去项目归属；M1 不尝试级联终止或迁移会话。

## 验证与限制

- 当前开发验收主机为 Windows；M1 先完成人工交互与进程树验证。macOS/Linux 的配置、目标平台构建及实机验收统一由 M5 跨平台门禁执行，不阻塞 M1–G4 的 Windows 阶段完成。
- Windows Job Object 只能在 PTY 子进程创建后通过其进程句柄附加，存在极短的 spawn/attach 间隔；实现须在附加失败时立即终止根进程并返回失败，自动化测试覆盖附加失败清理。若真实验证发现子进程能在附加前逃逸，必须改用可在创建时指定 Job 的 PTY 启动方案后才能验收。
- 高输出控制只保证限制本应用的未确认传输队列；xterm.js 自身滚屏保留行数也需设置上限，且不写入磁盘。

## 后果

- 新增 `portable-pty`、xterm.js 及 Fit addon 依赖，并增加 PTY 会话表和 IPC 命令。
- 输出回压与进程树管理增加实现复杂度，但可保持 UI 有界、输入独立和应用退出语义可验证。
- M1 暂时借用旧项目详情视图展示终端；M2 再迁移到正式工作台布局，M3 再加入多终端布局。

## 修订说明（2026-10-06，事实更新，不改变决策）

- 决策 7 中“复用全局与项目参数合并”描述的是 M1 时的实现；0.3.0 M2 已移除全局/项目自定义启动参数，当前 PTY 只用 CLI 默认行为加适配器的内部恢复参数（`launch_service.rs`、各适配器 `resume_args`）。
- “应用退出请求若有活动会话先交前端确认，不能绕过确认直接退出”当前有已知例外：macOS 的 Cmd+Q 等系统退出入口不产生可阻止的 `ExitRequested`，会绕过确认（S1C-N01，待修）。退出确认现在同时覆盖未保存文件缓冲；`confirm_app_exit` 尚未与待决请求关联（S3H-A02）。详见 `docs/architecture.md` 的“应用退出门与恢复门（现状）”与“已知限制与待收口项”。
- 本 ADR 的“输入独立”由每会话专用写线程和容量 32 的有界队列实现（`pty_session_service.rs`），单次输入上限 64 KiB，超限或背压返回 `pty_input_backpressure`；独立窗口所有者被销毁时由 `reclaim_window` 把会话回收给主窗口并缓冲输出，主窗口通过 `reattach_pty_session` 重新接管（M6 期间新增，见 `docs/architecture.md`）。
