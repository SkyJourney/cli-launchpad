# 产品路线图

本文档记录 CLI Launchpad 的产品方向和版本阶段。当前正式发布基线仍为 0.2.4；Windows 本地候选包已使用 0.3.0 版本号完成构建、安装和启动验证，但尚未正式发布。0.3.0 是一次以项目与内置终端为中心的产品形态转型；macOS/Linux 对齐完成并通过 M5 后，再决定正式 tag 与多平台发布。各阶段的范围和验收条件见 [`docs/milestones/0.3.0/`](milestones/0.3.0/README.md)。

## 当前产品方向

CLI Launchpad 从小窗口 CLI 启动器，演进为轻量级、本地优先的 CLI 会话工作台。主窗口以项目和内置 PTY 终端为中心，让用户在一个窗口中切换项目、查看并排列 Claude Code、Codex、Antigravity、Grok Build 与 Hermes Agent CLI 会话。

核心对象彼此独立：

- **项目**是终端会话的稳定归属。
- **PTY 会话**代表一个正在运行的 CLI 进程及其终端状态。
- **CLI 对话**是 CLI 自身的历史会话；如果能够可靠识别，则与 PTY 会话关联。
- **布局**描述终端面板的空间排列。布局预设可以引用会话，但不拥有会话，也不负责终止 PTY。

产品保持轻量，0.3.0 目标范围限定在 `claude`、`codex`、`agy`、`grok`、`hermes` 五项 CLI；Grok Build 与 Hermes Agent 分别通过独立 G1、G2 关卡接入。不建设通用 CLI 管理器、额度聚合、Agent 编排、worktree 管理或远程运行平台。

## 0.2.4 基线

0.2.4 是当前稳定基线，包含项目目录管理、通过外部终端启动 CLI、CLI 会话历史与恢复、参数配置、安装更新、执行任务、桌面托盘以及 Windows、macOS、Linux 平台支持。现有行为与迁移约束以产品需求、架构和 UI 设计文档为准。

## 0.3.0 里程碑

### M0：产品方向、架构边界与视觉标识

- 对齐轻量 CLI 工作台定位和 0.3.0 非目标。
- 定义项目、PTY 会话、CLI 对话和布局的数据关系及 PTY 生命周期/重启恢复语义；0.3.0 普通 CLI 工作流只使用内置终端。
- 确定大窗口优先的信息架构和跨平台统一圆角正方形产品图标。
- 验收：产品需求、架构、UI 设计和里程碑文档互相一致；应用包、应用内 Logo 与 README 使用统一品牌图形。

### M1：内置 PTY 核心闭环

- 在 Tauri + Rust 中实现 PTY 生命周期管理，并在 React 工作区内嵌终端模拟器。
- 打通创建、输入输出、尺寸变化、退出和终止；支持三个目标 CLI 与项目工作目录。
- 当前先完成 Windows 版开发和验收，再推进 M2–M4 的 Windows 实现。
- 验收：Windows 三项 CLI 可在内置终端中交互运行；正常退出和异常结束符合 M0 进程生命周期契约，不遗留失管进程。macOS/Linux 实机对齐不阻塞 Windows 阶段，统一记录在[跨平台对齐待办](milestones/0.3.0/cross-platform-alignment.md)，并作为 M5 发布门禁。

### M2：跨项目共享终端工作台

- 建立左侧项目维护、中间跨项目共享终端区、右侧三个内置 CLI 启动按钮与合并历史恢复区域，以及底部图标辅助入口。
- 项目新增/重命名使用弹窗；列表只显示项目名称。移除独立项目管理页和全局/项目自定义启动参数及模型选择。
- 普通 CLI 启动不再提供外部终端选项或命令预览；未检测到的 CLI 启动按钮禁用，历史恢复直接创建内置 PTY。
- 支持多项目递归终端窗格；每个窗格有自己的标题和会话切换，横纵分栏可多级组合并拖动边界调整大小；标题支持跨窗格移动和打开单会话独立窗口，关闭后会话返回主工作区；选择项目只高亮相关窗格并设置启动/恢复目标，不隐藏其他会话。
- Windows 阶段完成托盘、退出确认、窄窗口适配和终端尺寸安全边界。布局持久化与命名预设留给 M3。
- 验收：Windows 用户可在同一工作区交互操作多个项目的 CLI 会话；会话切换、分栏和项目高亮不会误关或串写其他 PTY。macOS/Linux 实机对齐仍按[跨平台对齐待办](milestones/0.3.0/cross-platform-alignment.md)纳入 M5。

### G1：Grok Build CLI 接入（独立里程碑）

- 在 M2 后、M3 前，把 Grok Build 纳入 0.3.0 四 CLI 工作台；G1 是独立接入门禁，不改写 M1/M2 已完成时的验收记录。
- 对齐官方 `grok` 命令的 Windows 检测、安装、更新、默认项目启动、`GB` 标题、会话 metadata 读取、项目内可重建搜索索引和 `--resume <session-id>` 恢复。
- 普通启动不开放自定义参数；只读取官方会话 summary metadata，不读取正文，也不调用可能混入远端结果的 `grok sessions search`。
- 验收：Windows 上完成检测、官方安装/更新计划与版本回读、PTY 输入输出/退出、当前项目会话列表/搜索/恢复以及错误和损坏数据测试；macOS/Linux 实机仍归 M5 对齐。

### M3：全局布局保存与会话恢复

**依赖：** M2、G1。

**Windows 状态：** 已完成实现、审查、自动门禁和用户实机验收；macOS/Linux 实机对齐转入 M5。

- 在 SQLite 自动保存当前跨项目工作区，并允许用户维护命名布局快照；前端须等待初始恢复完成后才允许自动保存。
- 保存递归分栏树、pane 编号、比例、slot 与 PTY 会话关联、活动标签、焦点、自动/自定义标题及必要的失效项展示信息；当前状态还记录独立窗口中的 slot，应用重启后移除这些已结束会话项并保留原窗格树。布局记录不拥有 PTY。
- 应用重启后将旧 PTY 标示为已结束并从当前工作区移除对应会话项，保留窗格与比例，不恢复终端输出或滚屏，也不自动启动 CLI；用户可在指定空窗格中通过历史会话恢复。项目或会话身份失效的引用继续显示诊断占位项。
- 应用命名快照只替换主工作区呈现结构，不迁移、关闭或启动 PTY 进程；快照外的主工作区运行 PTY 按稳定顺序优先保留到原 pane ID、其次保留到同编号窗格，均不存在时放入目标布局焦点窗格并去重。独立窗口会话保持独立，不参与窗格合并或重排，即使快照引用该会话也不将其移回窗格；其 slot 继续参与项目级 CLI 窗口序号计数。
- 当前布局自动保存；PTY 自然退出从当前布局移除会话项并保留空窗格，但不改写命名快照。应用命名快照时省略已结束会话项并保留窗格树。自动标题随项目重命名更新，自定义标题不变。
- 主窗口恢复上次大小和位置；启动时将恢复结果完整约束在当前显示器工作区内，显示器变化时回退可用显示器并在必要时降低窗口最小尺寸。
- SQLite 备份包含当前布局与命名快照；JSON 配置导入/导出不包含，也不覆盖布局。
- 验收：Windows 上恢复 pane tree、比例、标签、焦点和标题正确；布局应用不丢失运行会话；损坏布局、失效 session、项目删除或 ID 重用只生成局部占位项，其余窗格仍可用。

### G2：Hermes Agent CLI 接入（独立里程碑）

- 在 M3 完成后、M4 前，把 Hermes Agent CLI（`hermes`）作为第五项 CLI 纳入 0.3.0；终端标题简称为 `HA`。G2 不改写 M1–M3 已完成阶段的历史验收范围。
- 对齐 Windows 官方 CLI 检测、源码安装与更新所有权、当前/可用版本状态、项目内 PTY 启动、会话 metadata、项目内搜索和 `--resume <session-id>` 恢复。
- 会话从当前有效 Hermes home 对应 Profile 的 SQLite `state.db` 只读、有界读取；按 `source=cli` 与项目目录过滤，不扫描全文或 Hermes FTS 索引。恢复以 `--no-restore-cwd` 固定在当前项目目录。
- Windows 安装使用官方非交互模式，并跳过工作台不提供的可选浏览器与 computer-use 工具；更新状态查询校验官方安装归属，确认更新后由 Hermes 自身以默认语义处理，Launchpad 只执行已解析完整路径的 `hermes update`。
- 不接入 Hermes Desktop、Gateway、消息平台、远程服务或 Profile 管理；macOS/Linux 实机对齐留给 M5。
- 验收：Windows 上完成检测、官方安装/更新来源保护、PTY 输入输出/退出、当前项目会话列表/搜索/别名/恢复以及错误和损坏数据库隔离验证。

### G3：统一自定义窗口标题栏（独立里程碑）

**状态：** Windows 实机验收与自动门禁通过；macOS/Linux 配置、目标平台编译和窗口行为验收统一纳入 M5。

**依赖：** M2、M3、G2 Windows 实机验收。

- 主工作区和独立终端窗口统一使用自定义标题栏；主窗口移除左侧品牌标题行，将侧栏与布局操作固定到顶部。
- Windows/Linux 由应用绘制窗口控件并接管拖动、双击最大化/还原和需要的缩放命中区；macOS 保留原生红黄绿交通灯并用 overlay 标题栏展示应用操作。
- 自定义关闭操作复用托盘/退出确认和 PTY 交接生命周期；独立窗口的会话标题拖放与窗口移动手势明确分离。
- 验收：Windows 上主/独立窗口的标题栏、窗口控件、拖放/移动/缩放、托盘、PTY 退出保护与窗口恢复均通过用户实机验收；macOS/Linux 配置、目标平台编译及真机窗口验收统一由 M5 对齐清单覆盖。

### G4：主题、生命周期与适配边界治理

**依赖：** M2、M3，以及 G2、G3 Windows 实机验收通过。

**状态：** 已完成；自动门禁与最终代码审查通过，G4 五类 Windows 实机验收于 2026-10-02 由用户确认通过。独立窗口画布无法单独视觉确认的范围与处理方式已记入 G4 验收记录。

- 在 G2、G3 实机验收通过后开始渐进重构；验收发现的问题先回到对应里程碑闭环。
- 梳理并逐步明确主题偏好、语义 token、跨窗口同步和原生窗口外观的所有权，为后续新增主题保留稳定扩展边界。
- 复核 Rust PTY 会话真相与 React 工作区/独立窗口交接状态，整理重复、乱序、超时、退出和窗口关闭等状态转换及异步资源清理。
- 按职责渐进拆分工作区与终端视图，保持布局树、比例、焦点、输入、尺寸变化、标签拖动和独立窗口行为不变。
- 审查五项 CLI 的适配能力、默认安全降级、Rust/前端/SQLite 注册一致性和错误隔离；只增加静态穷尽性检查，不建设动态插件系统。
- 审计并清理 G3 全局样式变量矩阵和 CLI 适配器模式的无用 token/helper、重复注册顺序及会把缺失能力伪装成成功结果的默认实现；所有第三方组件、品牌与终端配色例外均记录理由。
- 验收：主题在主窗口和多个独立窗口间一致；单会话/单适配器故障不影响其他会话或应用生命周期；重构后的布局、PTY 交互、窗口交接和 CLI 能力与 G2/G3 已验收行为一致；全局样式与适配器残留完成清理；代码审查及自动、Windows 手工门禁通过。
- 详细阶段计划、覆盖场景、非目标与风险见 [G4 里程碑文档](milestones/0.3.0/G4-architecture-refactoring.md)。

### M4：现有能力接入与数据迁移

**依赖：** M2、M3、G1、G2、G3、G4。

**状态：** 已完成；自动门禁通过，Windows 实机验收于 2026-10-02 由用户确认通过。macOS/Linux 对齐归 M5。

- 复核已接入工作台的五项 CLI 历史/恢复、检测/安装更新、后台任务、配置交换、备份恢复、诊断和桌面设置，不重复实现已交付功能。
- 以 0.2.4 schema 8 / 配置 bundle v3 为升级基线，验证迁移到当前 schema 13 / bundle v4、保护备份、旧数据保留、失败恢复和旧参数隔离。
- 完成从工作台辅助视图往返及共享 PTY 会话上下文复核，并修复审查发现的缺口。
- 验收：自动门禁和 Windows 0.2.4 实机升级检查通过；macOS/Linux 对齐仍由 M5 执行。

### M5：跨平台验收与 0.3.0 发布

**状态：** Windows M1–M4、G1–G4 已完成；Windows 0.3.0 x64 NSIS 本地候选包已安装并启动验证。macOS/Linux 对齐待开始，未创建正式版本 tag。

- Windows M1–M4、G1–G4 完成后，按[跨平台对齐待办](milestones/0.3.0/cross-platform-alignment.md)完成 macOS/Linux 配置/目标平台编译、实机验证与必要适配，并复核 Windows、macOS、Linux 的 PTY、布局、窗口标题栏、项目切换、异常终止、安装包及升级路径。
- 更新用户文档、截图、发布说明和已知限制。
- 正式发布门禁：macOS/Linux 对齐与三平台发布检查完成，版本文件一致、文档就绪，并由用户确认后才创建正式 tag；推送匹配 tag 才触发 GitHub Actions 正式发布。
- 验收：三个平台具备可重复的发布检查记录，五项 CLI 的平台能力和关键 PTY 生命周期有证据；每个平台至少一项 CLI 完成真实交互启动，未安装或不适用项有明确记录；旧数据迁移均通过人工验收。

## 0.3.0 之后

根据 0.3.0 使用反馈再评估后台 PTY 守护进程、跨设备签名与公证、更多布局预设等能力。应用自身自动更新和远程 Agent 编排不属于当前承诺范围。
