# 产品路线图

本文档记录 CLI Launchpad 的产品方向和版本阶段。当前发布基线为 0.2.4；0.3.0 是一次以项目与内置终端为中心的产品形态转型。各阶段的范围和验收条件见 [`docs/milestones/0.3.0/`](milestones/0.3.0/README.md)。

## 当前产品方向

CLI Launchpad 从小窗口 CLI 启动器，演进为轻量级、本地优先的 CLI 会话工作台。主窗口以项目和内置 PTY 终端为中心，让用户在一个窗口中切换项目、查看并排列 Claude Code、Codex 与 Antigravity CLI 会话。

核心对象彼此独立：

- **项目**是终端会话的稳定归属。
- **PTY 会话**代表一个正在运行的 CLI 进程及其终端状态。
- **CLI 对话**是 CLI 自身的历史会话；如果能够可靠识别，则与 PTY 会话关联。
- **布局**描述终端面板的空间排列。布局预设可以引用会话，但不拥有会话，也不负责终止 PTY。

产品保持轻量，范围继续限定在 `claude`、`codex`、`agy` 三项 CLI。0.3.0 不建设通用 CLI 管理器、额度聚合、Agent 编排、worktree 管理或远程运行平台。

## 0.2.4 基线

0.2.4 是当前稳定基线，包含项目目录管理、通过外部终端启动 CLI、CLI 会话历史与恢复、参数配置、安装更新、执行任务、桌面托盘以及 Windows、macOS、Linux 平台支持。现有行为与迁移约束以产品需求、架构和 UI 设计文档为准。

## 0.3.0 里程碑

### M0：产品方向、架构边界与视觉标识

- 对齐轻量 CLI 工作台定位和 0.3.0 非目标。
- 定义项目、PTY 会话、CLI 对话和布局的数据关系、PTY 生命周期/重启恢复语义，以及显式外部终端备用入口。
- 确定大窗口优先的信息架构和跨平台统一圆角正方形产品图标。
- 验收：产品需求、架构、UI 设计和里程碑文档互相一致；应用包、应用内 Logo 与 README 使用统一品牌图形。

### M1：内置 PTY 核心闭环

- 在 Tauri + Rust 中实现 PTY 生命周期管理，并在 React 工作区内嵌终端模拟器。
- 打通创建、输入输出、尺寸变化、退出和终止；支持三个目标 CLI 与项目工作目录。
- 验收：Windows、macOS、Linux 的受控探针均能在内置终端中交互运行目标 CLI；正常退出和异常结束符合 M0 进程生命周期契约，不遗留失管进程。

### M2：大窗口工作台与项目切换

- 建立大窗口主框架、项目导航、终端工作区和可折叠的上下文区域。
- 在项目之间切换时聚焦对应项目会话，不因导航切换隐式关闭 PTY。
- 验收：用户可在同一应用窗口内打开多个项目并快速切换，主操作不再依赖系统外部终端窗口。

### M3：独立会话、多面板与布局预设

- 为 PTY 会话维护独立身份，并按项目、工具和可选 CLI 对话关联。
- 支持多个终端标签、分栏、面板尺寸调整和会话切换。
- 保存可选的项目布局预设；恢复布局时缺失或已退出的 PTY 明确显示为可恢复状态。
- 验收：移动、关闭或重排面板不会误操作其他 PTY；布局保存和恢复不改变会话归属。

### M4：现有能力接入与数据迁移

- 将会话历史、恢复、模型/参数、CLI 检测、安装更新、执行任务、配置备份和桌面设置接入新工作台。
- 定义旧版 SQLite、配置 bundle 和窗口状态升级路径。
- 验收：旧版用户数据可升级且核心功能可用；原有三项 CLI 功能在新工作区内有明确入口。

### M5：跨平台验收与 0.3.0 发布

- 完成 Windows、macOS、Linux 的交互式 PTY、布局、项目切换、异常终止、安装包及升级路径验收。
- 更新用户文档、截图、发布说明和已知限制。
- 验收：三个平台具备可重复的发布检查记录，关键 PTY 生命周期和旧数据迁移均通过人工验收。

## 0.3.0 之后

根据 0.3.0 使用反馈再评估后台 PTY 守护进程、跨设备签名与公证、更多布局预设等能力。应用自身自动更新和远程 Agent 编排不属于当前承诺范围。
